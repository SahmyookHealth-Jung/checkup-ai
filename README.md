# checkup-ai

건강검진 결과지를 읽어 국가건강검진 기준으로 판정하고, 공개 문서를 근거로 출처를 붙여 해설하는 AI 서비스다. 진단은 하지 않는다.

> **진행 중인 포트폴리오 프로젝트(README, 2026-11-12).** 아래 수치는 모두 합성 결과지로 잰 값이다. 목표를 못 채운 것도 그대로 적었다. 진행 기록은 [개발 일지](docs/devlog.md), 설계 결정은 [ADR](docs/adr/)에 있다.

**설계 원칙:** LLM은 결과지의 값을 베끼고, 근거가 있는 곳에서만 문장을 쓴다. 받아들일지와 판정, 고지와 진료 권고는 코드가 정한다. LLM을 어디에 쓰고 어디에 쓰지 않을지는 측정으로 정했다.

```
결과지 PDF ─▶ 추출 (Haiku, 구조화 출력) ─▶ 원문 대조 검증 (코드) ─▶ 기준 판정 (코드, 보건복지부 고시)
          ─▶ 근거 조회 (항목 코드) ─▶ 해설 문장 (LLM, 7개 항목만) / 고정 문구 (코드, 10개 항목)
          ─▶ 인용·숫자 검증, 진료 권고, 고지문 (코드)
```

## 주요 설계 결정

- **판정은 LLM이 아니라 코드가 한다.** 기준 수치는 보건복지부 고시(검사항목별 판정기준)에서 가져와 출처와 함께 데이터 파일에 둔다. 모르는 값 표기나 다른 단위는 판정하지 않고 "확인 필요"로 알린다 ([ADR 0007](docs/adr/0007-얇은-RAG-해설-설계.md)).
- **LLM 출력은 후보다.** 추출값은 원문에 있어야 받아들이고, 해설 문장은 허락된 근거를 인용하고 근거에 없는 숫자가 없어야 남긴다 ([ADR 0004](docs/adr/0004-추출-검증-원칙.md)).
- **입력이 닫힌 곳에는 검색을 쓰지 않는다.** 판정 해설은 항목 17개 × 판정이라 질의가 늘 같다. 유사도가 0.50~0.70에 몰려 임계값이 아무것도 가르지 못하는 것을 확인하고, 항목 코드 조회로 바꿨다. 검색은 입력이 열린 후속 질문에 쓴다 ([ADR 0010](docs/adr/0010-해설-두-경로-분리와-후속-질문.md)).
- **지표는 상한과 구조부터 본다.** 검색 P@4의 상한이 0.625인 것, 만점이 구조 때문인 지표를 따로 표시한다 ([ADR 0008](docs/adr/0008-5단계-의미-충실도-측정-중심.md)).
- **채점기도 검증한다.** 사람 라벨과의 일치도와, 오류를 일부러 심은 문장을 잡는지로 잰다 ([ADR 0009](docs/adr/0009-의미-충실도-채점기-설계.md)).
- **저비용·로컬 경로.** 기본은 Claude Haiku 5.5이고, 보내기 전에 식별정보를 지우며 호출마다 토큰·비용·지연을 기록한다. 데이터를 밖으로 보낼 수 없는 환경을 위해 로컬 모델 경로(오프라인 모드)를 둔다 ([ADR 0005](docs/adr/0005-추출-모델-선택.md), [ADR 0006](docs/adr/0006-LLM-호출-기록과-식별정보-제거.md)).

## 한계

- 결과지는 모두 합성 데이터다. 생성기의 어휘를 개발셋과 공유하므로 처음 보는 양식은 레이아웃 일반화만 잰다. 글자 층이 있는 PDF만 지원하고 스캔 이미지는 다루지 않는다.
- 진료 권고 73/73은 같은 판정 규칙과 같은 기준 데이터를 쓰는 두 구현(앱과 평가)의 일치다.
- 판정 해설에서 LLM이 쓰는 7개 항목 문장의 의미 충실도는 아직 재지 않았다. 해설 평가는 조건당 2회라 변동 폭을 말하기 어렵다.
- 라벨러는 개발자 1명이고 의료인이 아니다. 채점기와 리뷰는 같은 계열 모델(Claude)이 많다.
- 자세한 한계는 [ADR 0010 결과의 "측정의 한계"](docs/adr/0010-해설-두-경로-분리와-후속-질문.md)에 있다.

## 기술 스택

Java 21 · Spring Boot 4 · Spring AI 2 · PostgreSQL 18 + pgvector 0.8 · Claude Haiku 5.5(기본) · Ollama(bge-m3 임베딩, qwen3:4b 오프라인 모드) · Python(평가 스크립트). Gradle 멀티모듈(`core`, `report`, `app`) 구조는 [ADR 0002](docs/adr/0002-저장소-모듈-구조.md)에 있다.

## 빠른 시작

```bash
cp .env.example .env            # 값 채우기: POSTGRES_PASSWORD, ANTHROPIC_API_KEY (키는 .env에만, 커밋 금지)
docker compose up -d            # PostgreSQL + pgvector
ollama pull bge-m3              # 임베딩 모델 (Ollama 설치 필요)
cd backend && ./gradlew :app:bootRun
curl localhost:8080/actuator/health
```

- 화면: http://localhost:8080 ([ADR 0012](docs/adr/0012-화면-개편과-데모-예산.md))
  - 소개 `/`: 무엇을 하고 하지 않는지, 대표 수치와 한계
  - 해설 데모 `/demo.html`: 합성 샘플 결과지로 추출 → 판정 → 해설, 그리고 후속 질문
  - 품질 `/quality.html`: 평가 기록(실패 포함). 평가를 새로 돌리면 `(cd eval && .venv/bin/python build_dashboard_data.py)`로 데이터를 다시 만든다
  - 운영 `/ops.html`: LLM 호출 기록의 기능별·날짜별 호출, 비용, 지연
- 데모 하루 예산: 오늘 LLM 비용이 `checkupai.llm.budget.daily-usd`(기본 $0.20) 이상이면 데모 호출을 429로 막는다. 0이면 끈다
- 오프라인 모드(로컬 모델, 데이터를 밖으로 보내지 않음): `ollama pull qwen3:4b` 후 `SPRING_PROFILES_ACTIVE=offline ./gradlew :app:bootRun`. Intel CPU에서는 결과지 하나에 약 5분이 걸린다.
- 평가 명령은 [CLAUDE.md](CLAUDE.md)의 "명령어"에 있다. 평가 결과는 `eval/results/`에 커밋 해시와 함께 남는다.

## 만든 방식

Claude Code로 구현하고, 개발자가 설계를 결정하고 리뷰했다. 핵심 결정은 ADR에 "결정(사용자)"으로, 다른 모델(Codex, Fable)의 리뷰와 반영 여부는 [개발 일지](docs/devlog.md)의 "Claude Code 협업"에 남겼다.
