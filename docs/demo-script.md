# 시연 영상 대본 (약 3분)

녹화 전 준비
- `docker compose up -d`, `ollama serve`, `cd backend && ./gradlew :app:bootRun`
- 그날 평가를 돌렸다면 예산 상한에 걸릴 수 있다. 녹화 때는 `.env`에 `DEMO_DAILY_BUDGET_USD=1`로 올리고, 끝나면 되돌린다.
- 샘플은 `std-` 하나와 `nar-` 하나를 미리 한 번씩 돌려 둔다. 추출 결과가 메모리에 남아 녹화 때 기다림이 짧아진다.
- 녹화 비용은 약 $0.02(해설 2회, 후속 질문 5회 안팎)다.

## 1. 소개 (30초) — `/`

- "결과지를 읽고, 국가 기준으로 판정하고, 공개 문서를 근거로 설명합니다. 진단은 하지 않습니다."
- 처리 순서 카드에서 **LLM 칸은 둘뿐**(추출, 해설 문장)이고 나머지는 코드라는 점을 짚는다.
- "못 한 것과 한계" 상자를 보여 준다. 실패를 숨기지 않는 것도 보여 줄 거리다.

## 2. 해설 데모 (70초) — `/demo.html`

1. 샘플을 고르고 "해설 보기"를 누른다.
2. 결과 표에서 결과지 판정과 국가 기준 판정을 나란히 보여 준다. 판정은 코드가 고시 기준표로 한다.
3. 항목별 해설에서 문장 끝 `[n]`을 눌러 출처(문서·절·이용 조건)로 간다. 근거가 없는 항목은 "찾지 못했다"고 말한다.
4. 질환의심 항목의 진료 권고(빨간 띠)와 고지문을 보여 준다.

## 3. 후속 질문 (50초) — 같은 화면 아래

1. 항목 하나를 고르고 "이 판정이 무슨 뜻인가요?" → 출처가 붙은 답, 아래 메타데이터(근거 개수, 통과 문장 수, 생성 시간).
2. "제가 당뇨병인가요?" → **진단 질문이라 답하지 않음**(고정 문구). 모델이 답하려 했다면 "진단 규칙이 막았다"는 표시가 나온다.
3. "콜레스테롤 약을 먹어야 하나요?" → 약·치료 거절.
4. 노란 상자의 알려진 한계("질환 이름 없이 묻는 진단 질문은 놓칠 수 있다")를 읽어 준다.

## 4. 품질 (30초) — `/quality.html`

- 대표 수치 카드의 상태 표시(목표 달성 / 조건 있음 / 목표 미달)를 훑는다.
- "후속 질문" 표에서 시험 → 재확인 탭을 바꿔 보며, 빨간 칸(답하면 안 되는데 답함)이 어떻게 나왔고 무엇을 고쳤는지 말한다.
- "시험 몫은 한 번만 쟀고 그 결과로 프롬프트를 고치지 않았다", "고칠 때는 새 문항을 먼저 커밋했다".

## 5. 운영 (20초) — `/ops.html`

- 오늘 비용과 데모 하루 상한, 기능별 호출당 비용과 지연(중앙값·95%)을 보여 준다.
- "모든 LLM 호출은 토큰·비용·지연을 기록하고, 결과지 원문은 남기지 않습니다."

## 맺음 (10초)

- "LLM을 어디에 쓰고 어디에 쓰지 않을지를 측정으로 정했고, 못 채운 목표도 기록으로 남겼습니다."
