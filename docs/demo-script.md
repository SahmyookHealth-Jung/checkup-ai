# 시연 영상 대본 (약 3분)

녹화 전 준비
- `docker compose up -d`, `ollama serve`, `cd backend && ./gradlew :app:bootRun`
- 그날 평가를 돌렸다면 예산 상한에 걸릴 수 있다. 녹화 때는 `.env`에 `DEMO_DAILY_BUDGET_USD=1`로 올리고, 끝나면 되돌린다.
- 샘플은 `std-` 하나와 `nar-` 하나를 미리 한 번씩 돌려 둔다. 추출 결과가 메모리에 남아 녹화 때 기다림이 짧아진다.
- 녹화 비용은 약 $0.02(해설 2회, 후속 질문 5회 안팎)다.

## 1. 소개 (30초) — `/`

- 제목을 읽는다. "검진 결과지를 읽고, 국가 기준으로 판정하고, 근거가 있는 말만 합니다."
- 오른쪽 회색 상자를 가리킨다. "데모에서 실제로 나온 출력입니다." 판정 줄, 출처 `[3]`이 붙은 해설 문장, 거절한 진단 질문 순서로 짚는다.
- "된 것 / 안 된 것"을 같은 무게로 보여 준다. 안 된 것(후속 질문의 진단 질문 2건)도 첫 화면에 둔 이유를 한 문장으로 말한다.
- "누가 무엇을 하나"에서 **LLM이 하는 일은 둘뿐**(추출, 해설 문장)이고 판정·검증·권고는 코드라는 점을 짚는다.

## 2. 결과지 해설받기 (70초) — `/demo.html`

1. 제목 아래에서 샘플을 고르고 **해설 보기**를 누른다. 미리 한 번 돌려 둔 샘플이면 바로 나온다.
2. 표 위의 한 줄 요약("질환의심 3 · 정상B(경계) 1 · …")을 읽고, 표에서 결과지 판정과 국가 기준 판정을 나란히 보여 준다. 판정은 코드가 고시 기준표로 한다.
3. 항목별 해설에서 문장 끝 `[n]`을 눌러 출처(문서·절·이용 조건)로 간다. 근거가 없는 항목은 "찾지 못했다"고 말한다.
4. 질환의심 항목의 진료 권고(붉은 바탕 줄)와 맨 아래 고지문을 보여 준다.

## 3. 후속 질문 (50초) — 같은 화면 아래 "이 결과지에 대해 묻기"

1. 항목 하나(예: 공복혈당)를 고르고 예시 "이 판정이 무슨 뜻인가요?"를 누른 뒤 **질문하기** → 출처가 붙은 답과 아래 작은 글씨(근거 개수, 통과 문장 수, 생성 시간)를 보여 준다.
2. "제가 당뇨병인가요?" → **진단 질문이라 답하지 않음**(정해진 문구). 모델이 답하려 했다면 "진단 규칙이 막았다"는 표시가 붙는다.
3. "콜레스테롤 약을 먹어야 하나요?" → 약·치료 거절.
4. 질문 칸 위 붉은 상자의 알려진 한계("질환 이름 없이 묻는 진단 질문은 놓칠 수 있다")를 읽어 준다.

## 4. 평가 기록 (30초) — `/quality.html`

- 맨 위 요약 문장("9개 중 목표를 채운 것 4개, 조건이 붙은 것 3개, 못 채운 것 2개")을 읽고 표의 상태 열을 훑는다.
- "후속 질문" 절에서 **시험 40문항 → 재확인 16문항** 버튼을 바꿔 보며, 빨간 칸(답하면 안 되는데 답함)이 어떻게 나왔고 무엇을 고쳤는지 말한다.
- "시험 몫은 한 번만 쟀고 그 결과로 프롬프트를 고치지 않았다", "고칠 때는 새 문항을 먼저 커밋했다".

## 5. 운영 (20초) — `/ops.html`

- 맨 위 요약 문장(오늘 비용과 데모 하루 상한 대비 %, 최근 14일 호출 수·비용)과 예산 막대를 보여 준다.
- 날짜별 비용 막대에 마우스를 올려 기능별 비용을 보여 주고, 아래 표에서 호출당 비용과 지연(중앙값·95%)을 짚는다.
- "모든 LLM 호출은 토큰·비용·지연을 기록하고, 결과지 원문은 남기지 않습니다."

## 맺음 (10초)

- "LLM을 어디에 쓰고 어디에 쓰지 않을지를 측정으로 정했고, 못 채운 목표도 기록으로 남겼습니다."
