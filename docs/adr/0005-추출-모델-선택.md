# 0005. 추출 모델 선택: 기본은 Haiku, 식별정보는 로컬 경계에서 막고, 로컬 모델은 오프라인 모드로 둔다

- 상태: 채택 (2026-11-10)
- 날짜: 2026-11-10
- 관련: ADR 0001(채팅 LLM 미정), ADR 0004(추출 검증 원칙)

## 맥락

- 추출 검증(ADR 0004)은 소형 로컬 모델 qwen3:4b 하나로만 만들고 쟀다. 모델이 병목인지는 재 보지 않았다(외부 리뷰의 지적).
- 비교한 두 모델:
  - **qwen3:4b:** 로컬 Ollama, Intel CPU, think 끔.
  - **Claude Haiku 5.5:** `claude-haiku-5-5`, Anthropic API, thinking 끔(같은 조건). 가격은 100만 토큰당 입력 $0.10, 출력 $0.50.
- 한 모델을 validated 파이프라인(v2.4)으로 한 번 실행하면, 같은 LLM 출력으로 세 조건을 짝 비교할 수 있다(재생 비교).
  - 1차만: baseline과 같은 프롬프트
  - 검증만: 원문 대조
  - 검증+재요청
- 평가셋:
  - 개발셋: 양식 3종, 30개
  - 처음 보는 양식: 3종, 30개
  - 모두 합성 결과지다. 지표는 v2(OTHER 항목명 확인)다.
- 실서비스 제약: 검진 결과는 건강정보(민감정보)다. 외부 API로 보내면 국외 이전, 의료기관 보안 요건이 걸린다. 그래서 실제 검진센터에서는 외부 API를 그대로 쓸 수 없는 경우가 많다(구체 요건은 법무·보안 검토 사항).

## 측정 (2026-11-10, `eval/results/extraction/model-comparison.json`, `python -m extraction.compare_models`)

| 모델 | 평가셋 | 1차만 | 검증만 | 검증+재요청 | 보고서당 지연 | 보고서당 비용 |
|---|---|---|---|---|---|---|
| qwen3:4b | 개발셋 | 0.922 | 0.966 | **0.991**¹ | 283초 | $0 |
| qwen3:4b | 처음 보는 양식 | 0.866 | 0.893 | **0.925** | 309초 | $0 |
| Haiku 5.5 | 개발셋 | 0.995 | **0.995** | 0.995 | 5.2초 | $0.0011 |
| Haiku 5.5 | 처음 보는 양식 | 0.991 | **0.995** | 0.991 | 5.0초 (재요청 시 6.2초) | $0.0012 (재요청 시 $0.0013) |

¹ qwen3 개발셋은 v2.1 실행의 출력이다. 30개 중 5개는 재요청 입력이 v2.4와 달라 근사치다.

- 판정 필드 정확도(처음 보는 양식): Haiku 1차 81.3% → 검증 후 88.8%, qwen3 1차 70.0% → 검증 후 85.5%.
- Haiku 61회 실행(시험 1회 포함)의 실제 비용은 $0.075였다(입력 31만, 출력 8.7만 토큰).

## 해석

1. **모델이 병목이었다.**
   - Haiku는 1차만으로 qwen3의 검증+재요청보다 높다.
   - 처음 보는 양식에서의 하락폭(1차, 개발셋 대비)이 qwen3는 0.056, Haiku는 0.004다.
   - ADR 0004가 다룬 일반화 문제의 대부분은 작은 모델의 한계였다.
2. **원문 대조 검증은 모델과 무관하게 값이 있다.**
   - Haiku에서도 정밀도(처음 보는 양식 0.994 → 1.000)와 판정 필드 정확도(81% → 89%)를 올렸다.
   - 틀린 값을 지우는 쪽이라 비용·지연이 들지 않는다.
3. **재요청은 작은 모델에만 이득이다.**
   - qwen3에서는 재현율을 올린다(처음 보는 양식 0.834 → 0.891).
   - Haiku에서는 득이 없다. 비용 +8%, 지연 +24%가 들고, 5번째 양식에서 오히려 틀린 값을 만들었다.
     - 1차가 빠뜨린 신장·체중을 재요청이 다시 물었을 때, 3개년 표의 지난해 값(175.8)을 가져왔다.
     - 빈 값이 틀린 값으로 바뀐 것이다. "틀린 값보다 빈 값이 낫다"(ADR 0004)에 어긋난다.
4. **Haiku에도 남는 오류:** 줄바꿈된 흉부 X선 소견에서 전회 칸의 "정상"을 고른 것(3건)은 검증도 못 막았다. 글자 값 대조가 느슨하다는 ADR 0004의 한계와 같다.

## 결정

**프로젝트는 Haiku 5.5로 진행한다.** 식별정보는 외부로 보내기 전에 로컬에서 지우고, 로컬 모델 경로는 "오프라인 모드"로 유지한다. 모델과 재요청 여부는 설정으로 바꾸고, 코드는 같다.

| 구성 | 켜는 법 | 모델 | 파이프라인 | 쓰는 곳 |
|---|---|---|---|---|
| 기본 | (기본값) | Claude Haiku 5.5 | 검증만 (`validated-v2.4-noretry`) | 개발·평가·데모. 합성 데이터만 쓴다 |
| 오프라인 모드 | `SPRING_PROFILES_ACTIVE=offline` | qwen3:4b (Ollama) | 검증 + 재요청 (`validated-v2.4`) | 데이터를 밖으로 보낼 수 없는 환경. 이 맥에서는 로컬 경로 회귀 확인용 |

**역할 분담 (데이터 기준 하이브리드)**

| 일 | 어디서 |
|---|---|
| 외부 전송 전 식별정보 제거 (이름, 생년월일, 수검번호, 연락처 등) | 로컬 코드 |
| 결과지 추출 | Haiku (식별정보를 지운 텍스트) |
| 원문 대조 검증 | 로컬 코드 (원문 전체와 대조) |
| 임베딩 | 로컬 bge-m3 |
| 해설 생성 | Haiku (공개 가이드라인 + 식별정보 없는 수치) |

- **원칙:** 외부 API로 보내기 전에 식별정보를 지우고, 무엇을 보냈는지 기록한다(의료 가드레일 원칙 7, 개인정보 최소화).
  - 어디까지 지울지는 3단계(`core` 호출 기록)에서 정한다. 나이·성별·검진일은 추출에 필요하다.
  - 지금은 합성 결과지 전문을 그대로 보낸다.
- **재요청 설정:** `checkupai.extraction.retry-enabled`. 기본은 끄고, 오프라인 모드에서 켠다. 끄면 누락 조각은 진단 기록에만 남는다.
- **원칙 변경 (PROJECT_BRIEF 3절):** "개발 중에는 로컬(무료) 모델"을 "개발은 Haiku, 식별정보는 로컬 경계에서 차단"으로 바꾼다.
  - Haiku 비용은 보고서당 약 $0.001이다. 이 맥 CPU로 5분 걸리던 일이 5초에 끝난다.
  - 다음 단계(해설, 가드레일 공격 세트, LLM 채점)는 모델 호출이 많아 로컬 CPU로는 진행이 어렵다.
- **한계:** 식별정보를 지워도 검진 수치는 건강정보다. 이 설계는 반출을 최소화할 뿐, 법적 요건 충족을 뜻하지 않는다.

## 검토한 대안

- **Haiku로 단일화:** 가장 단순하고 정확하다. 하지만 데이터를 외부로 보낼 수 없는 검진센터 환경에서는 쓸 수 없다. 로컬 경로와 검증 파이프라인의 의미도 사라진다.
- **qwen3:4b로 단일화:** 무료이고 데이터가 밖으로 나가지 않는다. 하지만 이 노트북에서 보고서당 5분이 걸리고, 처음 보는 양식에서 0.925에 그친다. 이후 단계(RAG 해설) 개발 속도도 크게 떨어진다.
- **Haiku에도 재요청 유지:** 이득 없이 비용·지연이 늘고, 처음 보는 양식에서 틀린 값을 만들었다.
- **작업별 하이브리드 (쉬운 건 qwen, 어려운 건 Haiku):** 이 맥에서는 qwen 쪽이 병목이라 속도 이득이 없다. 데이터를 밖으로 보내는 문제도 풀지 못한다.
- **Sonnet 등 상위 모델:** Haiku가 이미 0.99대라 개선 여지가 작다. 비교하지 않았다.

## 한계

- 평가셋이 합성 텍스트 PDF 60개다. Haiku의 0.991과 0.995 차이는 오차 범위다.
- qwen3 지연은 Intel 노트북 CPU 기준이다. GPU 서버에서는 크게 줄어든다(이번에 재지 않음).
- 데이터 반출 가능 여부의 법적 판단은 이 ADR의 범위 밖이다.
