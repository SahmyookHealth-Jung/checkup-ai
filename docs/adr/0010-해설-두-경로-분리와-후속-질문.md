# 0010. 해설을 두 경로로 나눈다: 판정 해설은 조회와 코드 문구로 확정하고, 검색은 후속 질문 경로에서 쓴다

- 상태: 채택 (2026-11-11). 순서 1~3 완료, 판정 해설 경로 닫음 (2026-11-11)
- 관련: ADR 0007(5절 6번 "자유 질문 입력은 받지 않는다"를 바꾼다), ADR 0008(5절 "하이브리드·리랭킹 보류"와 4절 4번 짝비교 범위를 바꾼다), ADR 0009(채점기 쓰임새), 2026-11-11 전체 검토(Fable 5.2 세션)

## 맥락

2026-11-11 전체 검토에서 저장된 결과를 다시 계산해 확인한 것이다.

**검색이 할 일이 없다.**
- 청크는 83개이고 질의는 "항목명 + 판정" 고정 형식이다. 항목 17개 × 판정이라 결과가 늘 같다. 검색이 아니라 조회다.
- 유사도가 모두 0.50~0.70에 몰려 있다. 요단백 질의에서 정답 행은 0.532, 무관한 당뇨 청크는 0.496이다. 임계값 0.5는 아무것도 가르지 못한다.
- 주 지표 P@4의 상한이 0.625다. 질의 20개 중 11개는 정답이 2개뿐이라 만점이 0.5다. 기준선 0.50은 이미 상한의 80%다.

**5단계 개선이 모두 "AI를 덜 쓰는" 방향이다.**
- 코드 문구를 켜면 LLM 문장 436개 중 266개(61%)가 사라진다. LLM은 7개 항목만 쓴다.
- 항목 필터는 사실상 `item_code` 조회다.

**채점기를 믿을 근거가 부족하다.**
- 뒷받침 축의 눈가림 κ는 0.05(3단계) / 0.15(2단계)다.
- 판정 구간 축 κ 0.88은 "구간을 말했나"만 가른 값이다. 사람 라벨 50개에 "틀림"이 0개다.
- 치료·약 축도 사람 라벨 "있음"이 0개라 재현율을 모른다.

**판정 코드가 실제 표기에서 틀린다.** 기준 수치는 고시 원문과 17개 항목 모두 일치한다. 틀리는 곳은 값 해석이다.
- 흉부 "정상(특이소견 없음)", "정상A" → 질환의심 (거짓 경보)
- 요단백 "+/-" → 질환의심 (정상B가 맞다)
- 공복혈당 7.2 mmol/L → 정상A, 크레아티닌 88 μmol/L → 질환의심 (단위를 보지 않는다)
- "140 H", ">400", "1,120" → 판정하지 않고 경고도 없다
- 합성 데이터는 흉부 값 3종, 요단백 4종, 항목당 단위 1종뿐이라 평가가 이를 잡지 못한다.

**해설에는 성격이 다른 두 문제가 섞여 있다.**
- 판정 해설("이 수치는 어느 구간인가"): 입력이 닫혀 있다. 답이 정해져 있어 코드가 가장 잘한다.
- 설명과 질문("이게 무슨 뜻이고 뭘 조심해야 하나"): 입력이 열려 있다. 검색, 가드레일, 채점이 할 일이 있다. 지금은 이 경로가 없다.

## 결정 (사용자, 2026-11-11): B안, 두 경로로 나눈다

### 1. 판정 해설 경로: 조회로 확정한다
- 근거는 벡터 검색이 아니라 `item_code`로 찾는다.
- 근거가 판정기준표 1행뿐인 10개 항목은 코드 문구로 답한다 (ADR 0008 1절 그대로).
- 근거 글이 있는 7개 항목(혈압 2, 공복혈당, 지질 4)만 LLM이 문장을 쓴다.
- 이 경로는 여기서 닫는다. 남은 약점은 한계로 적는다.

### 2. 후속 질문 경로: 검색은 여기서 쓴다
- 해설 화면에 입력창을 하나 둔다. 수검자가 자기 결과에 대해 묻는다.
- 한 번의 질문과 한 번의 답이다. 대화 이력, 스트리밍, 이어지는 대화는 넣지 않는다.
- 답은 검색한 근거 문단으로만 쓰고 출처를 붙인다. 근거가 없으면 답하지 않는다.
- 진단 요청과 치료·약 질문은 답하지 않고 진료를 권한다 (가드레일 원칙 1, 5).
- 근거 문서를 넓힌다. 지금 3편(고혈압, 당뇨병, 이상지질혈증)에 간, 신장, 빈혈, 비만 등을 더한다.
- 하이브리드 검색과 리랭킹은 이 경로에서 전후를 비교한다.

### 3. 정답셋을 먼저 만든다
- 질문과 기대 결과를 검색을 돌리기 전에 정한다 (처음 보는 양식과 같은 규율).
- 기대 결과는 세 가지다: 찾아야 할 문단 / 거절해야 함 / 답할 수 없음.
- 라벨링은 사용자가 한다.

### 4. 판정 코드를 보완한다
- 단위를 확인한다. 기준과 다른 단위는 판정하지 않는다.
- 값을 정규화한다 (쉼표, 표시 기호, 괄호 설명).
- 판정 대상 항목인데 판정하지 못하면 "확인 필요"로 띄운다. 조용히 넘어가지 않는다.
- 합성 데이터에 실제 표기 변형을 더해 평가가 이를 잡게 한다.

### 5. 채점기는 검증부터 한다
- 지지로 확인된 문장에 오류를 심은 세트(구간 수치 바꾸기, 약 이름 넣기, 인용 바꾸기)로 축마다 재현율을 잰다.
- 큰 채점 비용은 후속 질문 경로가 생긴 뒤에 쓴다. 판정 해설 경로는 LLM 문장이 적다.
- ADR 0008 4절 4번의 개선 세 가지 짝비교는 "조회로 바꾼 전후" 한 번으로 줄인다.

## 순서 (제안)

1. 채점기 검증 (오류 심은 세트)
2. 판정 코드 보완과 합성 데이터 표기 변형
3. 판정 해설 경로를 조회로 확정, 전후 한 번 측정, 경로 닫기
4. 후속 질문 정답셋 (사용자 라벨링)
5. 근거 문서 확장과 청킹
6. 후속 질문 경로 기준선 (벡터 검색만) → 하이브리드·리랭킹 전후
7. 질문 가드레일 시험 (진단 요청, 약 질문, 답할 수 없는 질의, 악성 입력). ADR 0008 4절 5번의 "금지 표현 검사의 재현율"과 "악성 결과지(값·단위에 지시문을 심은 합성 PDF)"도 여기서 다룬다. 범위는 순서 7을 시작할 때 사용자가 정한다 (2026-11-12 방향 리뷰에서 빠진 것을 찾음)

## 아직 정하지 않은 것 (각 단계 시작 때 사용자가 정한다)

- **후속 질문 경로와 기능 2(Text-to-SQL)의 순서.** 추천은 후속 질문 먼저다.
- ~~**근거 문서 범위.**~~ → 정함(2026-11-12, 순서 4 결과): 4편(간·지방간, 만성콩팥병, 빈혈, 비만)을 더한다. 포털 글은 공공누리 유형을 편마다 확인한다.
- **키워드 검색 방식.** PostgreSQL 기본 전문 검색에는 한국어 형태소 분석이 없다.
- **질문 분류 방식.** 진단 요청·약 질문을 코드 규칙으로 가를지, LLM으로 가를지, 둘 다 쓸지.
- **LLM 문장의 근거 확인 방식.** 생성기가 근거 구절을 적고 코드가 대조할지, Anthropic Citations를 쓸지. Citations는 구조화 출력과 함께 쓸 수 없다.
- ~~**정답셋 구성.**~~ → 정함(2026-11-12, 순서 4 결과): 60문항(답 가능 30, 거절 15, 답 불가 10, 악성 5), 개발 20 / 시험 40.
- **대표 지표.** 후속 질문 경로에서 README 맨 위에 올릴 수치를 무엇으로 할지. 코드가 보장하는 값과 만점이 당연한 값은 대표 지표로 쓰지 않는다 (ADR 0008 3절).
- ~~**채점기 검증이 실패할 때.**~~ 순서 1에서 통과해 지금은 해당 없다. 대신 후속 질문 경로에서 채점기를 처음 쓸 때 채점 기준 v1.3(일반적인 치료 언급)을 반영하고, 보정셋과 오류 심은 세트를 다시 채점한다 (ADR 0009, 약 $1.2).

## 이 ADR이 다루지 않는 것

- **보여 줄 겉면.** 결과 중심 README, 화면 개편, 시연 영상, 저장소 공개는 6단계 그대로다. 이 ADR을 끝내도 6단계를 마치기 전에는 포트폴리오로 내놓을 수 없다.
- **공개 데모의 입력 정책.** 지금은 "공개 데모는 샘플만 허용"이다(ADR 0007 7절). 입력창이 생기면 누구나 유료 API를 부르게 된다. 호출 수 제한과 예산 상한을 6단계 착수 때 다시 정한다.
- **사용자가 직접 하는 일.** 정답셋 라벨링 말고는 정해 둔 것이 없다. 단계마다 투어나 직접 실행을 넣을지는 따로 정한다.

## 검토한 대안

- **A. 조회로 확정하고 닫기:** 작업이 가장 적다. 하지만 열린 입력을 받는 AI 기능이 없어지고, 만들어 둔 평가 도구가 잴 대상이 거의 없다.
- **C. 도구 호출형:** 모델이 기준 조회와 검색 도구를 직접 부른다. "코드가 판정한다"는 원칙과 충돌하고, 의료 맥락에서 무엇을 보고 답했는지 보장하기 어렵다.
- **후속 질문을 건너뛰고 Text-to-SQL로 가기:** 채점이 객관적이고 백엔드 포지셔닝에 맞는다. 하지만 기능 1에 검색 평가가 남지 않는다.

## 결과

### 순서 1. 채점기 검증 (2026-11-11)
오류 심은 세트 141문장으로 쟀다. 판정 구간 37/37, 치료·약 20/20, 대조 10/10, 인용 바꾸기 27/27. ADR 0009 "채점기 검증" 절.

### 순서 2. 판정 코드 보완 (2026-11-11)
표기 변형 평가셋 heldout-v4(146항목)를 만들었다. 거짓 경보 5 → 0, 조용히 지나감 5 → 4.
남은 4건은 추출 검증이 버린 값이었다. 추출 검증 v2.6으로 0이 됐다(ADR 0004 보완).

### 순서 3. 판정 해설 경로를 조회로 확정하고 닫음 (2026-11-11)

**결정(사용자):**
- 근거는 절 목록으로 조회한다(A안). 조회표 `explanation/evidence-lookup.json`이다.
  - 모든 항목은 그 항목의 판정기준표 행을 받는다.
  - 혈압 2, 공복혈당, 지질 4는 판정 구분 정의 하나와 정해 둔 절을 더 받는다. 고혈압은 개요-정의, 진단 및 검사, 생활습관 관리, 치료-비약물 치료다. 당뇨병은 개요-정의, 진단 및 검사, 생활습관 관리다. 이상지질혈증은 개요-정의, 진단 및 검사, 치료-비약물 치료다.
- 측정은 해설 평가만 한다. 충실도 채점은 후속 질문 경로에서 한다.

**구현:**
- 벡터 검색을 부르지 않는다. 근거 청크 파일을 바로 읽는다.
- LLM에 보낼지는 실제로 찾은 글 청크로 정한다. 글 청크가 없으면 코드 문구로 답한다(Codex 적대적 리뷰 반영).
- 5단계에서 켜고 끄던 두 개선(항목 필터, 코드 문구)은 고정하고 옵션을 없앴다.

**전후** (heldout30-v2.6, 해설 2회, 조회 전 7888437 / 조회 후 5da98a1, 둘 다 dirty=false):

| 지표 | 조회 전 (벡터 검색) | 조회 후 |
|---|---|---|
| LLM 문장 (남긴 것) | 437 / 436 | 176 / 176 |
| 문장 통과율 | 0.986 / 0.991 | 1.0 / 1.0 |
| 지운 인용 / 인용 없음 | 6·4 / 6·6 | 0 / 0 |
| 다른 항목 근거만 인용한 LLM 문장 | 107 / 121 | 0 / 0 |
| 진료 권고 | 73/73 | 73/73 |
| 금지 표현 기록 | 0 / 0 | 0 / 1 |
| LLM 호출 (60 요청 중) | 60 | 54 (3개 보고서는 LLM 항목이 없다) |
| 호출당 입력 / 출력 토큰 | 4,683 / 1,430 | 5,659 / 785 |
| 비용 (해설 60 요청) | $0.071 | $0.052 |
| LLM 지연 (보고서 평균) | 6.0초 | 3.3~3.6초 |

**읽는 법:**
- 통과율 1.0과 "다른 항목 근거만 인용 0"은 의미가 좋아졌다는 뜻이 아니다. 구조가 보장하는 값이다. 근거가 그 항목 것뿐이고 LLM 문장이 7개 항목에만 남기 때문이다. 대표 지표로 쓰지 않는다(ADR 0008 3절).
- 실제로 바뀐 것은 세 가지다.
  - LLM이 쓰는 범위: 17개 항목에서 7개 항목으로 줄었다.
  - 근거를 고르는 방식: 유사도에서 정해진 절로 바뀌었다.
  - 비용과 지연이 줄었다.
- 7개 항목 문장의 의미 충실도는 재지 않았다(사용자 결정).
- 금지 표현 1건은 공복혈당 문장이다. "진단기준 중 하나에 해당하지만 … 반복 확인해야 확진됩니다"처럼 "진단 및 검사" 절을 설명했다. 진단을 단정한 문장은 아니다. 하지만 이 절을 넣은 대가로 진단 용어가 문장에 들어온다.

**닫으며 남기는 한계:**
- 조회표의 절은 사람이 고른 것이다. 절이 바뀌거나 문서가 늘면 조회표를 고쳐야 한다. 저장소의 청크 파일과 맞는지는 `EvidenceLookupTest`가 확인한다.
- 공복혈당은 근거가 10청크로 가장 많다. 선별검사 대상 청크(`kdca-5305-diagnosis-3`)는 절 단위라 뺄 수 없었다.
- 해설 적절성 개선 후보(2026-11-11 보정 라벨 메모)는 다루지 않았다. 정상B 안내 부족, 크게 벗어난 수치의 별도 안내, 병 이름 대신 관리 안내 등이다.

### 순서 4. 후속 질문 정답셋 (2026-11-12 시작)

**결정 (사용자, 모두 추천안):**
- **질문을 먼저 쓰고 문단은 나중에 라벨링한다.** 질문은 근거 문서를 보지 않고 쓴다. 문서 표현을 따라 쓰면 검색이 실제보다 쉬워진다. 합성 결과지가 생성기 어휘를 공유했던 것과 같은 문제다. "찾아야 할 절"(`expectedSections`)은 순서 5(문서 확장) 뒤에 채운다. 단위는 절이다(고시는 행, 사용자 결정, 2026-11-12).
- **60문항:** 답 가능 30, 거절 15, 답 불가 10, 악성 5. 범주와 작성자로 층을 나눠 고정 시드(20261112)로 개발 20 / 시험 40을 나눈다. 시험 몫은 결과를 본 뒤 고치지 않는다. 고치면 새 이름으로 만든다.

- **다음 개선 후보:** 생활습관 문장은 근거에 있는 효과만 쓰도록 프롬프트에 한 줄을 더하는 것이다. → 아래에서 해 봤다.

**프롬프트 v2 짝비교 (사용자 요청, 커밋 3da7aa9, dirty=false):** 규칙 9를 더했다. 생활습관 효과는 근거가 바로 그 수치에 대해 말한 것만 쓰고, "운동이 LDL을 낮춘다" 같은 연결은 쓰지 않는다. 같은 고정 추출로 해설을 2회 다시 만들고(Haiku 54회 $0.052) 같은 채점기로 채점했다($2.73). 다른 세션이 화면 파일을 고치던 중이라, 같은 커밋의 깨끗한 git worktree에서 쟀다. 앱은 같은 커밋의 Java 코드로 다시 띄웠다.

- 나빠진 것은 없어서 v2를 그대로 둔다. 같은 세트에서 실패를 보고 고친 뒤 같은 세트로 잰 값이라, 효과가 있었더라도 일반화 수치는 아니다.

- **다른 방향 (효과는 미확인):** 후속 질문처럼 문장마다 근거 구절을 받아 코드가 대조하는 방식(followup-v2)을 판정 해설에도 쓰는 방법이 있다. 다만 후속 질문에서도 구절 대조 전후의 충실도를 비교한 적은 없다. 대조를 넣은 뒤 후속 질문 답의 충실도는 61%(시험)로 판정 해설보다 낮았다. 호출 구조가 바뀌는 일이라 하지 않았다.
- **정정 (2026-11-13):** 처음에는 이 절과 devlog에 "효과가 있었던 것은 코드 대조"라고 적었다. 근거를 다시 보니 측정으로 확인된 것은 "지시를 더하는 것보다 구조를 바꾼 쪽이 나았다"는 데까지다. 구조를 바꾼 예는 추출 원문 대조 0.951→0.989, 조회로 바꿔 다른 항목 근거 인용 107~121→0, 별도 분류 호출로 진단 요청 답변 22/36→1/36이다.

### 측정의 한계 (2026-11-12 방향 리뷰에서 확인)
수치를 인용할 때 함께 밝힌다.
- **heldout-v4는 "본 세트"다.** 표기 변형 평가의 "조용히 지나감 0, 거짓 경보 0"은 이 세트의 실패를 보고 판정 코드와 추출 검증을 고친 뒤, 같은 세트로 잰 값이다. ADR 0004의 규율("결과를 보고 규칙을 고치면 그 양식은 본 양식이 된다")대로 일반화 수치가 아니다. 표기 목록 자체는 측정 전에 정했다.
- **진료 권고 73/73의 하한.** 놓친 것 0건은 상한으로 적는다(ADR 0008 3절). n=73에서 재현율의 95% 신뢰 하한은 약 96%다(1 − 0.05^(1/73)).
- **판정은 두 구현이 같은 기준 데이터를 읽는다.** 앱(Java)과 평가(Python)가 모두 `criteria/general-screening-2026-6.json`을 쓴다. 73/73은 같은 규칙과 같은 데이터의 일치다. 기준 데이터는 고시 원문과 17개 항목을 대조했지만(2026-11-11 전체 검토), 원문 파일은 저장소에 없어 다시 재현할 수 없다.
- **해설 2회의 변동 폭.** 조회 후 2회 실행의 LLM 문장 수가 176/176으로 같았다. 2회로는 변동 폭을 말하기 어렵다.
- **라벨러는 1명이고 의료인이 아니다.** 보정셋 50문장 라벨과 오류 심은 세트 검토는 개발자 한 명이 했다(규칙으로 정해지는 수정 11칸은 Claude, 2026-11-11 devlog). 의료인 검토는 없다.
- **입력과 데이터:** 합성 결과지만 쓰고, 글자 층이 있는 PDF만 지원한다. 실제 양식 결과지와 스캔 이미지는 0건이다.
