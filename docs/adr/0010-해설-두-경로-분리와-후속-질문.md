# 0010. 해설을 두 경로로 나눈다: 판정 해설은 조회와 코드 문구로 확정하고, 검색은 후속 질문 경로에서 쓴다

- 상태: 채택 (2026-11-11)
- 관련: ADR 0007(5절 6번 "자유 질문 입력은 받지 않는다"를 바꾼다), ADR 0008(5절 "하이브리드·리랭킹 보류"와 4절 4번 짝비교 범위를 바꾼다), ADR 0009(채점기 쓰임새), 2026-11-11 전체 검토(Fable 5.2 세션)

## 맥락

2026-11-11 전체 검토에서 저장된 결과를 다시 계산해 확인한 것이다.

**검색이 할 일이 없다.**
- 청크는 83개이고 질의는 "항목명 + 판정" 고정 형식이다. 항목 17개 × 판정이라 결과가 늘 같다. 검색이 아니라 조회다.
- 유사도가 모두 0.50~0.70에 몰려 있다. 요단백 질의에서 정답 행은 0.532, 무관한 당뇨 청크는 0.496이다. 임계값 0.5는 아무것도 가르지 못한다.
- 주 지표 P@4의 상한이 0.625다. 질의 20개 중 11개는 정답이 2개뿐이라 만점이 0.5다. 기준선 0.50은 이미 상한의 80%다.

**5단계 개선이 모두 "AI를 덜 쓰는" 방향이다.**
- 코드 문구를 켜면 LLM 문장 436개 중 266개(61%)가 사라진다. LLM은 7개 항목만 쓴다.
- 항목 필터는 사실상 `item_code` 조회다.

**채점기를 믿을 근거가 부족하다.**
- 뒷받침 축의 눈가림 κ는 0.05(3단계) / 0.15(2단계)다.
- 판정 구간 축 κ 0.88은 "구간을 말했나"만 가른 값이다. 사람 라벨 50개에 "틀림"이 0개다.
- 치료·약 축도 사람 라벨 "있음"이 0개라 재현율을 모른다.

**판정 코드가 실제 표기에서 틀린다.** 기준 수치는 고시 원문과 17개 항목 모두 일치한다. 틀리는 곳은 값 해석이다.
- 흉부 "정상(특이소견 없음)", "정상A" → 질환의심 (거짓 경보)
- 요단백 "+/-" → 질환의심 (정상B가 맞다)
- 공복혈당 7.2 mmol/L → 정상A, 크레아티닌 88 μmol/L → 질환의심 (단위를 보지 않는다)
- "140 H", ">400", "1,120" → 판정하지 않고 경고도 없다
- 합성 데이터는 흉부 값 3종, 요단백 4종, 항목당 단위 1종뿐이라 평가가 이를 잡지 못한다.

**해설에는 성격이 다른 두 문제가 섞여 있다.**
- 판정 해설("이 수치는 어느 구간인가"): 입력이 닫혀 있다. 답이 정해져 있어 코드가 가장 잘한다.
- 설명과 질문("이게 무슨 뜻이고 뭘 조심해야 하나"): 입력이 열려 있다. 검색, 가드레일, 채점이 할 일이 있다. 지금은 이 경로가 없다.

## 결정 (사용자, 2026-11-11): B안, 두 경로로 나눈다

### 1. 판정 해설 경로: 조회로 확정한다
- 근거는 벡터 검색이 아니라 `item_code`로 찾는다.
- 근거가 판정기준표 1행뿐인 10개 항목은 코드 문구로 답한다 (ADR 0008 1절 그대로).
- 근거 글이 있는 7개 항목(혈압 2, 공복혈당, 지질 4)만 LLM이 문장을 쓴다.
- 이 경로는 여기서 닫는다. 남은 약점은 한계로 적는다.

### 2. 후속 질문 경로: 검색은 여기서 쓴다
- 해설 화면에 입력창을 하나 둔다. 수검자가 자기 결과에 대해 묻는다.
- 한 번의 질문과 한 번의 답이다. 대화 이력, 스트리밍, 이어지는 대화는 넣지 않는다.
- 답은 검색한 근거 문단으로만 쓰고 출처를 붙인다. 근거가 없으면 답하지 않는다.
- 진단 요청과 치료·약 질문은 답하지 않고 진료를 권한다 (가드레일 원칙 1, 5).
- 근거 문서를 넓힌다. 지금 3편(고혈압, 당뇨병, 이상지질혈증)에 간, 신장, 빈혈, 비만 등을 더한다.
- 하이브리드 검색과 리랭킹은 이 경로에서 전후를 비교한다.

### 3. 정답셋을 먼저 만든다
- 질문과 기대 결과를 검색을 돌리기 전에 정한다 (처음 보는 양식과 같은 규율).
- 기대 결과는 세 가지다: 찾아야 할 문단 / 거절해야 함 / 답할 수 없음.
- 라벨링은 사용자가 한다.

### 4. 판정 코드를 보완한다
- 단위를 확인한다. 기준과 다른 단위는 판정하지 않는다.
- 값을 정규화한다 (쉼표, 표시 기호, 괄호 설명).
- 판정 대상 항목인데 판정하지 못하면 "확인 필요"로 띄운다. 조용히 넘어가지 않는다.
- 합성 데이터에 실제 표기 변형을 더해 평가가 이를 잡게 한다.

### 5. 채점기는 검증부터 한다
- 지지로 확인된 문장에 오류를 심은 세트(구간 수치 바꾸기, 약 이름 넣기, 인용 바꾸기)로 축마다 재현율을 잰다.
- 큰 채점 비용은 후속 질문 경로가 생긴 뒤에 쓴다. 판정 해설 경로는 LLM 문장이 적다.
- ADR 0008 4절 4번의 개선 세 가지 짝비교는 "조회로 바꾼 전후" 한 번으로 줄인다.

## 순서 (제안)

1. 채점기 검증 (오류 심은 세트)
2. 판정 코드 보완과 합성 데이터 표기 변형
3. 판정 해설 경로를 조회로 확정, 전후 한 번 측정, 경로 닫기
4. 후속 질문 정답셋 (사용자 라벨링)
5. 근거 문서 확장과 청킹
6. 후속 질문 경로 기준선 (벡터 검색만) → 하이브리드·리랭킹 전후
7. 질문 가드레일 시험 (진단 요청, 약 질문, 답할 수 없는 질의, 악성 입력)

## 아직 정하지 않은 것 (각 단계 시작 때 사용자가 정한다)

- **후속 질문 경로와 기능 2(Text-to-SQL)의 순서.** 추천은 후속 질문 먼저다.
- **근거 문서 범위.** 어떤 주제를 몇 편 넣을지. 포털 글은 공공누리 유형을 편마다 확인한다.
- **키워드 검색 방식.** PostgreSQL 기본 전문 검색에는 한국어 형태소 분석이 없다.
- **질문 분류 방식.** 진단 요청·약 질문을 코드 규칙으로 가를지, LLM으로 가를지, 둘 다 쓸지.
- **LLM 문장의 근거 확인 방식.** 생성기가 근거 구절을 적고 코드가 대조할지, Anthropic Citations를 쓸지. Citations는 구조화 출력과 함께 쓸 수 없다.
- **정답셋 구성.** 전체 개수와 범주별 개수.
- **대표 지표.** 후속 질문 경로에서 README 맨 위에 올릴 수치를 무엇으로 할지. 코드가 보장하는 값과 만점이 당연한 값은 대표 지표로 쓰지 않는다 (ADR 0008 3절).
- **채점기 검증이 실패할 때.** 심은 오류를 잡지 못하면 채점 기준을 고칠지, 채점 모델을 바꿀지, 구절 대조 같은 코드 검사로 대신할지.

## 이 ADR이 다루지 않는 것

- **보여 줄 겉면.** 결과 중심 README, 화면 개편, 시연 영상, 저장소 공개는 6단계 그대로다. 이 ADR을 끝내도 6단계를 마치기 전에는 포트폴리오로 내놓을 수 없다.
- **공개 데모의 입력 정책.** 지금은 "공개 데모는 샘플만 허용"이다(ADR 0007 7절). 입력창이 생기면 누구나 유료 API를 부르게 된다. 호출 수 제한과 예산 상한을 6단계 착수 때 다시 정한다.
- **사용자가 직접 하는 일.** 정답셋 라벨링 말고는 정해 둔 것이 없다. 단계마다 투어나 직접 실행을 넣을지는 따로 정한다.

## 검토한 대안

- **A. 조회로 확정하고 닫기:** 작업이 가장 적다. 하지만 열린 입력을 받는 AI 기능이 없어지고, 만들어 둔 평가 도구가 잴 대상이 거의 없다.
- **C. 도구 호출형:** 모델이 기준 조회와 검색 도구를 직접 부른다. "코드가 판정한다"는 원칙과 충돌하고, 의료 맥락에서 무엇을 보고 답했는지 보장하기 어렵다.
- **후속 질문을 건너뛰고 Text-to-SQL로 가기:** 채점이 객관적이고 백엔드 포지셔닝에 맞는다. 하지만 기능 1에 검색 평가가 남지 않는다.
