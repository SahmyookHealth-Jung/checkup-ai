# 0009. 의미 충실도 채점기: 문장마다 호출하고, 3단계 라벨로 판정하며, thinking 설정은 보정셋에서 고른다

- 상태: 채택 (2026-11-11)
- 관련: ADR 0008 2절(채점 원칙)·4절 3번, devlog 2026-11-10 "5단계 2번, 기준선"

## 맥락

- 기준선(heldout 30개)은 형식 지표로는 거의 만점이었다. 문장 통과율은 0.99, 진료 권고는 73/73이었다.
- 하지만 통과한 873문장 중 81문장(9%)은 다른 항목의 기준표 행만 인용했다. 근거가 문장을 실제로 뒷받침하는지는 채점기로 재야 한다.
- ADR 0008이 정한 원칙은 아래와 같다. 이 ADR은 남은 구현 선택을 정한다.
  - 채점 모델: Sonnet 5.5
  - 채점 단위: 문장
  - 기준: 3축
  - 구절 확인: 채점기가 적은 구절이 청크에 있는지 코드가 본다
  - 보정: 사람 라벨 약 50문장으로 κ를 잰다
- 비용 추정의 근거(기준선 1회분)
  - 문장 436개, 항목 150개
  - 문장당 인용 근거는 평균 1.3개, 약 270자다
  - Sonnet 5.5 가격(100만 토큰당): 입력 $2, 출력 $10, 캐시 읽기 $0.10

## 결정 (사용자, 2026-11-11)

1. **호출 단위는 문장마다다.**
   - 보내는 것: 문장, 그 문장이 인용한 근거, 항목·결과값·판정 구간·판정 기준
   - 같은 항목의 다른 문장은 보내지 않는다. 문장끼리 판정에 영향을 주지 않게 하려는 것이다.
   - 채점 기준(시스템 프롬프트)은 프롬프트 캐싱으로 재사용한다.
   - 1회분은 약 $1.5로 추정한다(thinking 끔 기준).
2. **"근거가 뒷받침하는가" 축은 지지 / 부분 / 미지지 3단계다.**
   - 통과는 "지지"만이다.
   - 부분: 근거 있는 내용과 없는 내용이 섞인 문장(예: 기준 설명 뒤에 "생활습관을 점검하세요")
   - κ는 3단계와 2단계(지지 vs 나머지)로 둘 다 적는다.
   - 나머지 두 축의 라벨
     - 판정 구간: 맞음 / 틀림 / 말하지 않음
     - 치료·약 언급: 없음 / 있음
   - "뒷받침"은 **그 문장이 인용한 근거만** 보고 판단한다. 내용이 항목 정보와 맞아도 인용이 엉뚱하면 미지지다.
     - 사용자가 인용 번호를 눌러 확인하는 것은 근거 문단이기 때문이다.
     - 판정 구간 축은 항목 정보(결과값, 판정, 판정 기준)와 비교한다.
   - 정의는 `eval/rag/faithfulness_rubric.py` 한 곳에 두고, 라벨링 화면과 채점기가 함께 쓴다.
3. **보정셋 라벨링은 로컬 HTML 화면에서 한다.**
   - 화면 구성: 문장과 근거 원문을 나란히 보여 주고, 버튼으로 고른 뒤 라벨 JSON을 내려받는다. 서버는 없다.
   - 화면 파일에는 근거 원문(포털 글, 공공누리 제4유형)이 들어가므로 커밋하지 않는다. 라벨(문장 id + 판정 + 메모)만 커밋한다.
   - **사용자는 채점기 결과를 보기 전에 라벨링한다(눈가림).**
   - 50문장은 기준선 1회차에서 시드를 고정해 층별로 뽑는다.
     - 다른 항목 기준표만 인용한 문장 20개
     - 이웃 구간 위험이 있는 공복혈당·혈압 문장 10개
     - 나머지에서 무작위 20개
4. **thinking 설정은 보정셋에서 비교해 고른다.**
   - 비교할 두 조건은 "thinking 끔"과 "낮은 effort"다. 각각 50문장 × 3회를 채점한다.
   - 사람과의 일치도(κ), 자기 일치도, 비용을 보고 하나를 고른다. 고른 근거는 이 ADR의 결과 절에 적는다.

## 진행 순서

1. 보정셋 추출과 라벨링 화면을 만든다. 사용자가 라벨링한다.
2. 채점기를 구현한다. 라벨링과 동시에 할 수 있다. 사용자 라벨을 보지 않고 만든다.
3. 보정을 돌린다. 두 설정 × 50문장 × 3회다.
4. κ가 충분하면 기준선 2회분을 채점한다.

**비용 실측 (2026-11-11, 시험 호출 3문장 × 2설정):**
- 호출당 약 $0.006이다 (입력 약 500토큰, 캐시 읽기 약 2,000토큰, 출력 약 300토큰).
- 출력이 비용의 절반 이상이라 처음 추정보다 높다.
- 다시 추정한 비용
  - 보정: 약 $1.7
  - 기준선 1회분(436문장): 약 $2.5
  - 5단계 채점 전체: 약 $20

## 보완 (2026-11-11, 1차 라벨링 뒤): 채점 기준 v1.1

**1차 라벨(50문장)에서 발견한 것**
- "다른 항목의 근거만 인용" 층 20문장 중 15개가 "지지"였다. 일부는 인용 근거에 같은 말이 있어 맞지만, 상당수는 "인용한 근거에 있는 말인가"가 아니라 "맞는 말인가"로 판단됐다.
- 구간을 말하지 않은 문장에 "맞음"을 고른 경우가 있었다.
- 생활습관 권유와 자가 측정 권유를 "치료·약 있음"으로 고른 경우가 있었다. v1 기준이 이 경우를 정하지 않았다.
- **라벨링 화면과 채점기 프롬프트에 성별이 없었다.** 성별마다 기준이 다른 항목을 판단할 수 없었다 (구현 결함).
- 메모 중 일부는 충실도가 아니라 해설의 **적절성** 지적이었다. 예: "정상B인데 상의하라는 말뿐", "수치가 크게 벗어나면 다른 말이 필요". 개선 후보로 따로 남긴다 (devlog).

**결정 (사용자)**
- 생활습관 개선 권유(식이, 운동, 금연, 절주, 체중 관리)와 자가 측정 권유는 **치료·약이 아니다.** 치료·약은 약 이름·계열, 용량, 복용 변경, 처방, 시술·수술 같은 특정 치료법이다. 의료 가드레일 원칙 5와 같은 범위다.
- 판단 요령 6줄을 기준에 더한다(`faithfulness_rubric.GUIDE`). 라벨링 화면 맨 위와 채점기 시스템 프롬프트에 같은 글로 넣는다.
- 항목 정보에 성별을 넣는다. 고정한 추출의 보고서 성별(판정 코드가 쓴 값)이다.
- **재라벨링은 1차 라벨을 미리 채운 화면에서 고치는 방식으로 한다.** 빠르지만 1차 선택에 끌리기 쉽다는 한계를 적어 둔다.
- 1차 라벨은 `calibration-v1.labels-faithfulness-v1.json`으로 남긴다. κ는 v1.1 라벨로만 계산한다. 1차와 2차 라벨이 얼마나 바뀌었는지도 결과에 적는다.

## 검토한 대안

- **항목마다 한 번 호출:** 캐싱을 쓰면 1회분 $0.3 정도 싸다. 하지만 앞 문장이 뒤 문장 판정에 영향을 줄 수 있고, ADR 0008의 "문장 단위"와도 어긋난다.
- **지지 / 미지지 2단계:** 라벨링이 빠르고 κ가 높게 나오기 쉽다. 하지만 섞인 문장의 처리가 매번 흔들리고, 개선 후 "부분 → 지지" 변화가 보이지 않는다.
- **CSV·스프레드시트 라벨링:** 만들 것은 가장 적다. 하지만 긴 근거 원문을 셀에서 읽기 어렵고, 입력 오류를 나중에 걸러야 한다.
- **thinking 기본값(켬, effort high):** 판단이 가장 꼼꼼할 수 있다. 하지만 5단계 채점 전체가 $30을 넘을 수 있고, 근거 없이 정하게 된다.

## 결과

### 1차 보정 (2026-11-11, 기준 v1.1, 50문장 × 3회, 사람 라벨 v1.1과 비교)

| 축 | thinking 끔 | 낮은 effort |
|---|---|---|
| 뒷받침 일치율 / κ (3단계) / κ (2단계) | 0.50 / −0.03 / 0.04 | 0.38 / −0.09 / −0.04 |
| 판정 구간 일치율 / κ | 0.90 / 0.80 | 0.92 / 0.84 |
| 치료·약 일치율 | 1.00 | 0.94 (채점기만 "있음" 3건) |
| 자기 일치도 (뒷받침) | 0.88 | 0.98 |
| 비용 (150회) | $0.68 | $0.65 |

뒷받침 축은 서로 반대 방향인 두 원인이 섞여 κ가 0 근처였다.
- **채점기가 너무 엄격 (기준의 빈칸):** 결과값 문장(cal-020, 031, 040, 047)을 "결과값이 근거에 없다"며 부분으로 봤다. 진료 권유 문구(cal-008, 030)를 근거 없는 조언으로 셌다.
- **사람이 놓친 의미 오류 (채점기가 3회 모두 같은 판정):**
  - cal-014, 036: 근거는 "이상지질혈증이 신질환·간질환과 연관"인데 문장은 "간장질환이 신질환과 연관"으로 방향을 뒤집었다. 숫자 검사로는 잡을 수 없는 오류다.
  - cal-001, 013, 029, 041: 중성지방·혈압 기준표만 인용하고 그 표에 없는 설명을 했다.
  - cal-005, 015: 허리둘레 기준표에 없는 "BMI와 함께 보면 도움"을 말했다.

**결정 (사용자)**
- 채점기 설정은 **thinking 끔**이다. 사람과 더 맞고, 치료·약을 과하게 잡지 않는다.
- 기준 v1.2에 판단 요령 두 줄을 더한다.
  - 결과값과 그 값의 구간 적용은, 근거가 기준을 담고 있으면 지지다.
  - 진료 권유 문구는 근거가 없어도 감점하지 않는다.
- 사람 라벨은 고치지 않는다. κ는 채점기 판단을 보기 전 라벨(눈가림)로만 계산한다. "채점기가 잡은, 사람이 놓친 의미 오류"는 따로 적는다.
  - 사람 라벨 v1.1은 v1.2가 푸는 두 경우를 이미 지지로 봤다. 그래서 내용을 바꾸지 않고 v1.2 라벨로 쓴다 (`labels-faithfulness-v1.2.json`, `derivedFrom`).

### 2차 보정 (2026-11-11, 기준 v1.2, thinking 끔, 50문장 × 3회)

| 축 | 1차 (v1.1) | 2차 (v1.2) |
|---|---|---|
| 뒷받침 일치율 / κ (3단계) / κ (2단계) | 0.50 / −0.03 / 0.04 | 0.62 / 0.05 / 0.15 |
| 판정 구간 κ | 0.80 | 0.88 |
| 치료·약 일치율 | 1.00 | 0.96 (cal-045, 050: "해당 질환의 치료도 함께 이루어져야") |
| 자기 일치도 (뒷받침) | 0.88 | 0.98 |
| 비용 | $0.68 | $0.67 (보정 전체 $2.0) |

**κ가 낮게 남은 이유**
- 사람 라벨이 지지 42/50으로 쏠려 있다. 그래서 일치율이 올라도 κ가 낮다.
- 남은 불일치 19개를 Claude가 분류하고, 사용자가 확인했다 (아래 "사람 확인").
  - 정도 차이만 (둘 다 통과 아님): 3
  - 사람이 적절성 판단을 뒷받침 축에 섞음: 3 (cal-004, 025, 026. 근거에는 그대로 있다)
  - 사람이 놓친 근거 없는 내용: 8 (cal-001, 005, 013, 014, 015, 019, 029, 041)
  - 기준대로면 채점기가 맞음: 2 (cal-037 생활습관 점검 조언, cal-040 구간 수치가 인용 근거에 없음)
  - 채점기가 엄격한 편: 2 (cal-030, 032)
  - 기준의 빈칸: 1 (cal-035, 고혈압·당뇨·이상지질혈증용 정의를 다른 항목에 적용. 뒷받침 축은 이 경우를 다루지 않는다)

**사람 확인 (2026-11-11)**
- 정도 차이만 있는 3개를 뺀 16개를 확인 화면에서 봤다. 화면에는 사람 라벨, 채점기 판정과 이유, Claude 분류를 함께 보였다.
- 사용자는 16개 모두 Claude 분류에 동의했다 (`calibration-v1.disagreement-review.json`).
- 조정 라벨로도 일치도를 계산했다. "채점기가 맞다"로 확인된 13개(사람이 놓침 8, 적절성 혼입 3, 기준대로면 채점기 2)는 채점기 판정으로 바꿨다.

| 뒷받침 축 | 눈가림 라벨 (주 지표) | 조정 라벨 (보조) |
|---|---|---|
| 3단계 일치율 / κ | 0.62 / 0.05 | 0.88 / 0.75 |
| 2단계 일치율 / κ | 0.68 / 0.15 | 0.94 / 0.86 |

- 조정 라벨은 채점기 이유와 Claude 분류를 본 뒤 정한 값이라 **독립적이지 않다.** 16개 전부 동의한 데는 제시된 분류를 따르는 경향도 섞였을 수 있다.
- 그래서 "사람과 독립적으로 맞았다"는 근거는 눈가림 κ뿐이다. 조정 라벨 κ는 "채점기가 적어 둔 기준을 사람이 확인한 해석대로 적용한다"는 근거로만 쓴다.

**이 채점기를 어떻게 쓰나**
- 같은 채점기로 전후를 재는 **짝비교**에 쓴다. 판정 구간(κ 0.88)과 치료·약 관문은 그대로 믿는다.
- 보고할 때는 아래를 함께 적는다.
  - 눈가림 κ (0.05 / 0.15)
  - 조정 라벨 κ (0.75 / 0.86)와 그 한계
  - 뒷받침 절대 통과율이 엄격한 쪽으로 치우친 값이라는 점
- 같은 계열 모델(Claude가 분류, Sonnet이 채점)이라는 한계가 여기서도 남는다. 다른 계열 교차 채점(Codex)은 선택 과제로 둔다.
