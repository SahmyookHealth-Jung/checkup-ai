# 0013. 기능 2 Text-to-SQL: LLM이 SQL을 쓰고, 코드가 겹겹이 막는다

- 상태: 채택 (2026-11-13, 사용자 결정)
- 관련: PROJECT_BRIEF 기능 2, ADR 0002(모듈 `stats`), ADR 0006(LLM 호출 기록), ADR 0008(대표 지표 원칙)

## 맥락

7단계는 관리자용 통계 어시스턴트다. 관리자가 한국어로 물으면 SQL로 집계해 표로 답한다. 기능 1이 "LLM 출력은 후보이고, 받아들일지는 코드가 정한다"였듯이, 여기서도 LLM이 쓴 SQL은 후보다. 실행 여부와 범위는 코드와 DB 권한이 정한다.

## 결정 (사용자, 2026-11-13)

1. **생성 방식: LLM이 SQL을 직접 쓰고, 안전장치를 겹겹이 둔다.**
   - Claude Haiku 5.5가 스키마 설명(테이블·컬럼·코드값 뜻)과 질문을 받아 SQL 한 문장을 쓴다.
   - 코드는 다음을 검사한다: 한 문장인지, SELECT(또는 WITH … SELECT)인지, 허용한 테이블만 쓰는지. 실행은 결과 행 수 상한(LIMIT)과 문장 시간 제한(statement_timeout)을 걸고 한다.
   - 실행은 `stats` 스키마에 SELECT 권한만 있는 **읽기 전용 DB 계정**으로 한다. 앱의 다른 테이블(`llm_call_log`, `guideline_chunk`)은 그 계정으로 볼 수 없다.
   - 검사나 실행에서 오류가 나면 오류 내용을 붙여 **1회만** 다시 쓰게 한다.
   - 답할 수 없는 질문(데이터에 없는 정보, 개인 식별, 쓰기 요청)은 LLM이 구조화 출력으로 "답하지 않음"을 낼 수 있다.
2. **데이터: 공공데이터포털 "국민건강보험공단_건강검진정보" 한 해 전체(약 100만 행) + 코드표.**
   - 2023년 파일(`국민건강보험공단_건강검진정보_2023.zip`, 이용허락 제한 없음)을 쓴다.
   - 표 하나(`stats.checkup`)와 코드표(시도, 연령대 등)를 둔다. 원본 파일은 gitignore이고, 적재 스크립트와 스키마(Flyway)만 커밋한다.
3. **안전장치: 작은 집단 숨김까지 둔다.** 결과의 각 행이 나타내는 사람 수가 10명 미만이면 그 행의 값을 숨긴다.
   - 표본이 익명화돼 있어도 조건을 좁혀 개인을 짚는 질문을 막는다.
   - 집계가 아닌 개인 단위 행(가입자 일련번호 등)은 돌려주지 않는다.
4. **평가 정답셋: 60문항(개발 20 / 시험 40), Claude가 질문과 정답 SQL을 쓰고 사용자가 검토한다.**
   - 정답 SQL은 실행해서 결과를 확인하고 고정한다.
   - 범주는 단순 집계, 묶어 세기, 조건, 코드표 조인, 비율, 상위 k, 답할 수 없는 질문, 악성 요청이다.
   - 대표 지표는 **실행 결과 일치율**(정답 SQL과 결과 집합이 같은가)과 **막아야 할 요청을 실행한 건수**(목표 0)다.
   - 정답셋은 프롬프트를 쓰기 전에 만들고 커밋한다. 결정은 개발 몫으로만 하고, 시험 몫은 한 번만 잰다.

## 대안

- **LLM은 질의 계획(JSON)만, SQL은 코드가:** 더 안전하고 정확하지만 표현할 수 있는 질문이 좁고 Text-to-SQL로서 보여 줄 것이 적다. 필요하면 나중에 같은 정답셋으로 비교한다.
- **10만 행 표본, 여러 해:** 10만 행은 작은 집단이 많아져 숨김에 걸리는 결과가 늘어난다. 여러 해는 해마다 컬럼이 조금씩 달라 정리할 일이 늘어난다.
- **질문을 사용자가 절반 이상 쓰기:** 기능 1에서는 그렇게 했다. 이번에는 속도를 택했다. 대신 아래 한계가 생긴다.

## 한계

- 질문과 정답 SQL을 모두 Claude가 쓴다. 질문이 모델 말투에 가깝고 정답 SQL의 해석이 모델의 해석과 같을 수 있어서 점수가 부풀려질 수 있다. 사용자 검토로 일부만 줄인다.
- 결과 일치는 정답 SQL 하나의 해석 기준이다. 질문의 다른 합리적 해석은 틀린 것으로 센다.

## 보완 (2026-11-13, Codex 적대적 리뷰 → 사용자 결정 A안)

**리뷰 지적 (high 2, medium 1, 모두 직접 확인):**
1. 검사가 "집계 함수가 어딘가에 있는지"만 봐서 개인 행이 통과했다. `SELECT height_cm, weight_kg, fasting_glucose, (SELECT COUNT(*) FROM checkup) AS n FROM checkup`을 읽기 전용 계정으로 실행하면 개인 행이 n=100만과 함께 나왔다.
2. 숨김이 LLM이 쓴 n을 믿었다. `AVG(height_cm) FILTER (WHERE 세종·80~84세·남자·흡연)`에 `COUNT(*) AS n`을 붙이면 5명의 평균(157.0)이 n=100만으로 나왔다.
3. 평가의 숫자 기준 일치는 이름 열을 버려서, 이름을 뒤바꾼 답도 맞게 센다.
- Codex가 든 예시 중 둘은 실제 유출이 아니었다. 키 구간별 인원표는 정상 집계이고, 흡연자 수를 n으로 붙인 전체 평균은 큰 집단의 값이다. 위 두 SQL은 같은 구멍을 실제로 뚫는 예시다.

**바꾼 것 (커밋 2491b63, dd4f892)**
- **SQL 구조 검사 (JSqlParser 5.3):**
  - SELECT 하나만 받는다(서브쿼리·WITH·UNION·INTO·DISTINCT 금지). 테이블은 3개만 쓴다(쉼표 조인·따옴표 이름도 파서가 찾는다).
  - 집계 질의만 받는다(GROUP BY가 있거나 모든 반환 열이 집계).
  - 함수는 허용 목록만 쓴다: COUNT·AVG·SUM·PERCENTILE_CONT(0.25·0.5·0.75만)·ROUND·COALESCE·NULLIF·ABS·CAST. FILTER·OVER·MIN·MAX는 금지한다.
- **서버가 센 인원으로 숨김:** 반환 열의 집계마다 `COUNT(*)`와 `COUNT(인자)`를 숨은 열로 덧붙인다. 그중 가장 작은 인원이 10 미만이면 행을 숨긴다. LLM이 쓴 n은 보여 주기만 한다.
- **숨긴 행의 글자도 가림:** 숨긴 행에서는 코드표 이름과 SQL에 직접 쓴 문자열만 남긴다. 리뷰에 없던 우회로, 값을 글자로 바꿔(`CAST(fasting_glucose AS text)`) 묶음 이름으로 내보내는 경우를 막는다.
- **프롬프트 stats-sql-v2:** 규칙을 검사와 맞췄다. n=COUNT(*), 비율은 `AVG(CASE ...)`, 빈 값은 WHERE에서 뺀다.
- **평가:** 대표 지표를 **이름 정규화 일치**로 바꿨다. 뜻이 같은 이름("현재도 피운다"="현재 흡연")은 맞추고, 뒤바꾼 이름은 틀리게 센다. 숫자 기준은 진단용으로만 둔다. v1을 다시 세면 개발 33/34, 시험 27/34로 숫자 기준과 같다. 엄격 기준에서 틀린 것은 이름 글자만 다른 경우였다는 뜻이다.

**공격 문항 6개 (stats-attack-v1, 실행 전에 커밋)**
- 1차(attack-v2)에서 **새 우회를 찾았다.** "감마지티피 최댓값과 최솟값"에 대해 검사가 MIN/MAX를 막았다. 그러자 LLM이 다시 쓰면서 `PERCENTILE_CONT(0)`/`(1)`로 바꿔 1과 9999를 냈다. 다시 쓰게 할 때 준 거절 이유가 다른 길을 알려 준 셈이다.
- 그래서 백분위를 사분위수로 제한했다(dd4f892).
- 2차(attack-v2.1) 결과: 거절 4, 실행됐지만 숨김 2(5명 집단 평균, 세종 85세 이상 혈당값별 21행), **숨김 없이 나간 작은 집단 값 0**. 2차에서는 최댓값 요청을 LLM이 처음부터 거절해서, 백분위 제한은 단위 테스트로만 확인했다.

**남은 한계**
- 두 질의의 차이로 작은 집단을 알아내는 차분 공격은 막지 못한다. 예: "세종 85세 이상 전체"와 "세종 85세 이상 남자"의 차이.
- 비율의 분자가 작은 경우(예: 50명 중 3명)는 비율×n으로 알 수 있다. 숨김은 묶음 인원(분모)과 집계 인자의 인원 기준이다.
- `/api/stats/ask`에는 인증이 없다(데모 하루 예산만 있다).

## 정답셋 v2 (2026-11-13, 사용자 검토)

- 사용자 검토(외부 의견 포함)의 지적을 실제 DB와 test-v2 결과에 하나씩 대 봤다. 지적된 문항은 시험에서 모두 맞았다. 고쳐도 정답 결과가 바뀌는 지적은 없었다(시력 0 값 0건, 성별 NULL 0건, 혈압 한쪽만 빈 행 0건, 비율 분모는 프롬프트 규칙 6).
- 질문이 두 가지로 읽히던 시험 문항 3개만 고쳐 **stats-gold-v2**로 만들었다. sq-012 "차이" → "비교", sq-037 상위 5개 → 2곳(3·4위 반올림 동점), sq-049 "20대" → "20대 전체를 하나로 묶은". 나머지 57문항과 개발·시험 나눔은 v1과 같다.
- 시험 몫은 다시 재지 않는다. 시험 수치는 v1 기준 32/34(깨끗한 기준값 27/34) 그대로다. 틀린 2건(sq-037, sq-049)은 모델 잘못이라기보다 정답셋이 애매했던 탓이다. 다음 측정부터 v2를 쓴다(`run_stats_eval --gold`, 기본값 v2).
