# 0008. 5단계: 검색 알고리즘 비교보다 의미 충실도 측정을 먼저 하고, 근거가 기준표뿐인 항목은 코드 문구로 답한다

- 상태: 채택 (2026-11-10)
- 관련: ADR 0007(한계와 5단계 과제), devlog 2026-11-10 "4단계 끝" 방향 리뷰(Sonnet 5.5 세션, Codex)

## 맥락

**4단계 수치 중 해설 LLM의 품질을 직접 말하는 값이 거의 없다.**
- 고지문 포함률 100%와 진료 권고 문구는 코드 상수다.
- 진료 권고 재현율은 추출(Haiku)과 판정 코드를 합친 끝에서 끝까지의 지표다. 또 실패를 본 개발 보고서 10개에서 보완한 뒤에 잰 값이다.
- "문장 통과율"은 인용 번호와 숫자 검사를 통과한 비율이다. 의미가 맞는 비율이 아니다.

**LLM에 건네는 근거 목록의 질이 낮다.**
- 허락된 근거의 정밀도(P@4)가 평균 0.50이다.
- 판정 항목 17개 중 10개는 근거가 판정기준표 1행뿐이다(BMI, 허리둘레, 혈색소, AST, ALT, 감마지티피, 요단백, 크레아티닌, eGFR, 흉부방사선). 남는 자리는 다른 항목이나 다른 질환의 청크가 채운다.
- 숫자 검사는 인용한 청크 중 어느 것의 숫자든 인정한다. 그래서 다른 항목의 기준 수치를 써도 통과한다.
- hit@1을 놓친 5개 중 2개(공복혈당 질환의심, 수축기 혈압 질환의심)는 같은 항목이지만 다른 구간이나 다른 목적의 문단이 1위였다. 하나는 공복혈당장애 설명이고, 하나는 치료 목표와 약물 계열을 담은 요약문이다. 숫자 검사를 통과하는 의미 오류의 원형이다.

**가드레일에도 빈틈이 있다.**
- 약물 치료 절을 뺐지만, 고혈압 요약문 청크에 약물 계열 이름이 들어 있다.
- 금지 표현 정규식(5개)이 좁다.
- "근거 없음" 가드레일은 구조상 한 번도 발동하지 않았다. 질의가 항상 우리 항목명이기 때문이다.

## 결정 (사용자, 2026-11-10)

### 1. 근거가 기준표 1행뿐인 항목은 코드 문구로 답한다
- 위 10개 항목은 LLM 해설을 쓰지 않는다.
  - 코드가 판정 결과와 기준 문구로 "결과값은 국가건강검진 기준 ○○ 구간(기준)입니다 [1]"을 조립한다.
  - 출처는 그 항목의 판정기준표 행이다.
- 근거에 없는 상식이 숫자 없는 문장으로 섞이는 경로가 사라진다.
- 포털 글은 나중에 한 묶음씩 더한다. 그때 해당 항목의 "코드 문구 → LLM 문장" 전후를 충실도로 잰다.

### 2. 의미 충실도 채점
- **채점 모델:** Claude Sonnet 5.5(API). 생성 모델(Haiku)이 자기 답을 채점하면 같은 사각지대를 공유한다.
- **채점 단위:** 문장. 문장이 인용한 근거 전체를 함께 보고, 어느 인용이 뒷받침하는지 기록한다.
- **기준 3축**
  - 근거가 문장을 뒷받침하는가
  - 판정 구간이 맞는가
  - 치료·약 언급이 없는가
- **구절 확인:** 채점기는 뒷받침하는 구절을 원문 그대로 적는다. 코드는 그 구절이 청크에 실제로 있는지 확인한다.
- **별도 관문:** 약물·위험 관련 실패는 평균에 섞지 않는다. 목표는 0건이다.
- **완결성:** 결과값과 판정 구간을 말했는지는 코드로 확인한다.
- **보정**
  - 사용자가 개발 보고서에서 뽑은 약 50문장을 라벨링한다.
  - 실제 실패 사례(요단백, ALT)와 이웃 구간 문단 같은 어려운 오답을 섞는다.
  - 채점기와 사람의 일치도(κ), 채점기 자기 일치도를 적는다.
  - 채점기가 틀린 사례는 사람이 표본으로 점검한다.
- 같은 계열(Anthropic) 모델끼리 채점한다는 한계는 숨기지 않고 적는다.

### 3. 지표를 다시 나눈다
- **해설 LLM 지표:** 의미 충실도, 지운 인용, 근거 없는 숫자
- **끝에서 끝까지 지표:** 진료 권고 재현율. 놓친 원인을 추출, 판정, 대상 상한(max-items)으로 나눠 적는다.
- **코드가 보장하는 값:** 고지문 포함률, 권고 문구
- **검색 지표**
  - 주 지표는 허락된 근거의 정밀도(P@4)와 충실도다. hit@4와 MRR은 보조로 둔다.
  - 정답셋 v1은 고치지 않고, hit@1 0.75를 계속 보고한다.
  - 단계 라벨(정답/관련/무관)을 실험 전에 고정한 v2는 따로 만든다.
- 건수가 작은 지표는 비율이 아니라 건수로 적는다. 0건은 상한으로 적는다.

### 4. 순서
1. 단위 테스트 CI
2. 지표 재정의와, 처음 보는 양식(heldout-v1~v3) 30개의 기준선
   - 추출 결과를 저장해 고정하고, 저장한 추출로 해설만 돌리는 경로를 만든다.
   - 코드는 커밋으로 고정한다. 결과를 보고 고친 뒤의 수치는 처음 보는 데이터의 수치로 쓰지 않는다.
3. 채점기와 보정셋
4. 개선을 하나씩 짝비교
   1. 항목 필터: 해당 item_code를 가졌거나 item_codes가 빈 청크만 통과시킨다.
   2. 코드 문구(1절)
   3. 약물 이름 누수 차단(청킹 테스트 포함)
   - 각각 전체 수치와, 근거 목록이 바뀐 항목의 수치를 함께 적는다.
   - 조건당 2회 돌린다. 변동 폭을 가늠하는 수준임을 밝힌다.
5. 공격 질문 세트 대신 세 가지를 시험한다.
   - 답할 수 없는 질의 탐색(임계값 0.5)
   - 금지 표현 검사의 재현율
   - 악성 결과지(값·단위에 지시문을 심은 합성 PDF)

### 5. 하지 않는다
- **하이브리드·리랭킹 전면 비교:** 질의가 "항목명 + 판정"으로 고정돼 있고 자유 질문이 없어서 효과를 보여 주기 어렵다. 자유 질문을 넣을 때 다시 본다.
- hit@1 올리기, 정답셋 사후 수정, 보고서 단위 평가셋을 50~100개로 늘리기, 해설 스트리밍, 오프라인 모드 해설
- README와 예산 상한은 6단계에서 한다.

## 검토한 대안
- **브리프 원안**(하이브리드·리랭킹, 공격 질문 세트, 평가셋 50~100개 + LLM 채점)
  - top-4를 모두 LLM에 주므로, 검색 순위는 해설에 거의 영향이 없다.
  - 자유 질문이 없어서 공격 질문 세트로 시험할 입력 경로가 없다.
- **근거가 기준표뿐인 항목에 다른 방식을 쓰기**
  - 근거를 자기 행과 판정 정의로 제한하고 LLM이 1~2문장을 쓴다: 숫자 없는 상식 문장을 코드로 막을 수 없다.
  - 포털 글을 먼저 추가한다: 라이선스 확인, 청킹, 평가 확장을 한꺼번에 해야 하고 전후 측정이 없어진다.
- **Haiku 자기 채점:** 싸지만 같은 사각지대를 공유한다. 다른 계열(Codex) 교차 채점은 보정셋에 한해 선택 사항으로 둔다.
- **(문장, 청크) 쌍 단위 채점:** 인용이 여럿인 문장에서 근거를 합쳐야 뒷받침되는 경우를 오답으로 센다.
- **근거 목록이 바뀐 항목만 비교:** 선택 편향이 생긴다. 그래서 전체 수치와 함께 적는다.
