# 0007. 4단계 얇은 RAG 해설: 코드가 항목을 고르고 위험을 판정하며, 해설 문장은 인용과 숫자를 코드로 검증한다

- 상태: 채택 (2026-11-10)
- 관련: ADR 0004(추출 검증 원칙), ADR 0005(기본 Haiku), ADR 0006(식별정보 제거·호출 기록), CLAUDE.md 의료 가드레일 원칙 1~7, devlog 2026-11-10 방향 리뷰

## 맥락

- 1~3단계는 추출, 모델 선택, 호출 기록에 집중했다. 브리프가 "가장 중요"라고 적은 RAG 해설과 그 평가는 아직 시작하지 않았다.
- 4단계 목표는 **얇게라도 끝까지 잇는 것**이다. 결과지 → 추출 → 근거 검색 → 출처 붙은 해설 → 화면 순서로 처음부터 끝까지 동작하게 만든다. 깊게 파는 일(하이브리드, 리랭킹, 채점)은 5단계에서 한다.
- 추출에서 얻은 원칙("LLM은 후보를 내고, 코드가 원문과 대조해 받아들일지 정한다")을 해설에도 그대로 쓴다.

## 결정 (사용자, 2026-11-10)

### 1. 범위 밖 수치: 버리지 않고 "확인 필요"로 남긴다
- 지금은 가능 범위 밖의 값(공복혈당 1120 등)을 읽기 오류로 보고 버린다. 그래서 가장 위험한 값이 해설에 닿지 못한다(ADR 0004 한계).
- 앞으로는 이런 값을 "확인 필요(판독 불가)" 항목으로 응답에 남긴다. 화면에는 고정 문구 "결과지 원본을 확인하고 의료진과 상담하세요"를 띄운다(가드레일 원칙 3). 해설 대상에서는 뺀다.

### 2. 근거 문서
- 보건복지부 고시 「건강검진 실시기준」(판정 기준 표)과 질병관리청 국가건강정보포털의 항목 설명 2~3편(고혈압, 당뇨병, 이상지질혈증)을 쓴다.
  - 고시는 저작권법상 보호받지 않는 저작물이다.
  - 포털 글은 공공누리 유형을 확인한 뒤 쓴다.
- `data/guidelines/sources.yaml`에 URL, 발행기관, 고시번호 또는 게시일, 라이선스, 수집일을 적는다. 원문은 `data/guidelines/raw/`에 두고 gitignore한다.
- 문서 내려받기는 파일마다 사용자 확인을 받는다.
- 판정 기준 표는 PDF 표가 깨지므로(ADR 0004 "같은 줄 ≠ 같은 칸") 손으로 행 단위 텍스트를 만들고 출처 쪽수를 단다.

### 3. 청킹과 검색 (기준선)
- 절·항목 단위로 구조 청킹한다. 기준 표는 "표 머리 + 항목 한 행"을 한 청크로 한다.
- 메타데이터는 문서명, 기관, 고시번호/게시일, 쪽·절, 관련 ItemCode를 저장한다.
- 임베딩은 로컬 bge-m3다. 검색 질의는 코드가 "항목명 + 판정 구분"으로 만들고, 벡터 상위 4개를 쓴다.
- ItemCode 필터와 하이브리드 검색은 5단계에서 효과를 비교하려고 미룬다.

### 4. 해설 구조: 코드가 고르고, LLM은 문장만, 코드가 검증한다
- **코드가 정하는 것**
  - 해설할 항목: 결과지 판정이 정상이 아닌 항목과, 기준 데이터상 주의 범위인 항목.
  - 위험 판정: 기준 수치는 출처가 붙은 데이터 파일에 둔다(가드레일 원칙 6).
  - 결과지 참고치와 국가 기준이 다르면 둘 다 보여 주고 판정하지 않는다.
- **LLM이 내는 것:** 구조화 출력 `{itemCode, sentences: [{text, citations: [청크 id]}]}`만 낸다.
- **코드가 검증하는 것**
  - 인용 id가 이번 검색 결과 안에 있는가.
  - 문장 속 숫자가 추출값이나 인용한 청크에 있는가.
  - 실패한 문장은 버린다. 남은 문장이 없으면 "근거를 찾지 못했습니다"로 답한다.

### 5. 첫날부터 넣는 가드레일 (모두 코드로 강제)
1. 모든 응답에 고지문을 코드가 붙인다(원칙 4).
2. 인용 없는 문장은 지운다(원칙 2).
3. 검색 유사도가 임계 미만이면 "근거 없음"으로 답한다.
4. 위험 판정 항목과 확인 필요 항목에는 고정 문구로 진료를 권고한다(원칙 3).
5. 진단·치료 지시 금지(원칙 1, 5)는 프롬프트에 넣는다. 금지 표현 패턴 검사는 차단하지 않고 위반만 기록한다(5단계에서 측정).
6. 자유 질문 입력은 받지 않는다.

### 6. 인용 형식
- 문장 끝에 `[1]`을 붙인다.
- 아래에 "문서명 · 발행기관 · 고시번호/게시일 · 쪽/절 · URL"을 둔다.
- 누르면 청크 원문을 펼쳐 보여 준다.

### 7. 화면: Spring 정적 HTML 한 장
- app 모듈의 정적 리소스로 만든다. 흐름은 합성 샘플 선택(또는 PDF 업로드) → 추출 표 → 항목별 해설 카드와 출처 → 고지 배너다. "합성 데이터 데모"라고 표시한다.
- 공개 데모는 샘플 선택만 허용한다. 실제 결과지가 외부 API로 나가지 않게 하기 위해서다.

### 8. 식별정보 제거와 근거 문맥
- 근거 청크를 사용자 메시지에 넣으면 식별정보 제거 Advisor(ADR 0006)가 청크 속 전화번호·주소 모양을 바꿀 수 있다.
- 적재한 청크 전체에 제거기를 돌려 바뀌는 건수를 센다. 0이 아니면 근거 문맥을 시스템 메시지로 옮긴다.

### 9. 4단계에서 심어 둘 측정 (5단계의 기준선)
1. **검색:** 질의 15~20개(ItemCode × 판정 구분 → 정답 청크)로 hit@4와 MRR을 잰다. 정답셋은 청킹·프롬프트를 조정하기 전에 만든다(처음 보는 양식과 같은 규율).
2. **해설 검증:** 인용 유효율과 숫자 근거율. 4번의 코드 검증이 그대로 내는 값이다.
3. **진료 권고 재현율:** 위험 수치를 심은 합성 결과지 10~20개에서 권고가 나온 비율과 고지문 포함률을 잰다. Haiku는 출력이 흔들리므로 3회 반복의 범위로 적는다.
4. **비용·지연:** `llm_call_log`의 `report.explanation` 기능으로 남긴다. 검색·임베딩 지연은 따로 잰다.

### 10. 미룬다
하이브리드 검색, 리랭킹, 채팅·후속 질문, LLM 채점, 공격 질문 세트, 스트리밍, 이미지·OCR, 오프라인 모드의 해설(오프라인 모드는 추출 전용).

## 검토한 대안
- **Spring AI `QuestionAnswerAdvisor`:** 검색 결과를 프롬프트에 붙여 주는 기본 기능이라 빠르다. 하지만 인용 검증과 위험 판정을 코드로 강제하기 어렵다.
- **LLM 자유 해설:** 결과 전체를 보고 자연스럽게 쓴다. 근거 검증과 진단 금지를 보장할 수 없다.
- **고시만 쓰기:** 가장 안전하다. 하지만 해설이 기준 설명 위주로 딱딱해진다.
- **학회 진료지침 포함:** 내용이 풍부하다. 하지만 복제·인용 범위가 불확실하다.
- **React + Vite(브리프 원안):** 프론트 역량을 보여 준다. 하지만 4단계를 두껍게 만든다. 백엔드 포지셔닝에는 정적 HTML로 충분하다.

  - 제거 규칙도 "라벨과 값 사이에 콜론이나 공백"으로 고쳤다. 식별정보 잔존율 0%는 유지됐다.

| 진료 권고 정밀도 / 고지문 포함률 | 1.00 / 100% |

- **보고서당 비용과 지연:** 해설 $0.0013·6.8초(검색 0.3초 포함), 추출 $0.0011·5.4초. 합쳐서 약 $0.0025, 12초.

**측정하며 바꾼 것**
- **해설 출력 상한을 2,000에서 4,000토큰으로 올렸다.** 8개 항목 해설이 2,000토큰에서 잘려 실패했다.
  - 잘려도 완성된 항목까지 살린다. 추출과 같은 변환기다.
- **성별 기준 항목은 성별을 몰라도 두 성별 판정이 같으면 그 판정을 쓴다.**
  - 계기: 추출이 성별을 놓친 보고서에서 감마지티피 196의 진료 권고가 빠졌다.
  - 두 성별 판정이 다르면 지금처럼 판정하지 않는다(거짓 경보 방지).

## 한계와 5단계 과제
- **의미 충실도를 검증하지 않는다.**
  - 지금 검증은 "인용이 그 항목에 허락된 근거인가"와 "숫자가 근거에 있는가"까지다.
  - 실제 사례: 요단백 문장이 공복혈당 기준표를 인용했고, ALT 문장이 이상지질혈증 글을 근거로 "여러 원인과 연관될 수 있다"고 썼다. 둘 다 검증을 통과했다.
  - 5단계에서 LLM 채점(근거 충실도)으로 잰다.
- **판정 구분 정의 청크가 1위로 올라오는 질의가 있다**(hit@1 0.75). 항목에 느슨하게 관련된 청크도 유사도 0.5를 넘어 "허락된 근거"가 된다. 하이브리드 검색, 항목 필터, 리랭킹의 비교 대상이다.
- **결과지 판정과 국가 기준 판정이 다를 때** 화면에 둘 다 보여 줄 뿐, 해설은 국가 기준으로만 한다.
- **평가셋이 좁다.** 해설 평가는 개발 양식 3종 10개, 검색 정답셋은 20개다. 처음 보는 양식과 실제 표기는 시험하지 않았다.
- **추출이 성별을 놓치는 경우**(서술형 "남성")가 있다. 위 보완으로 위험 판정 누락은 막았지만, 추출 자체는 고치지 않았다(ADR 0004 이후 추출은 닫음).
