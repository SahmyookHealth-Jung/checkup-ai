# ADR 0015: 공개 데모 배포 구성 — 비용 0원, 샘플 해설과 후속 질문만

- 상태: 채택 (2026-11-13). 배포함: https://checkup-ai-pp8r.onrender.com (Render 싱가포르 + Neon 싱가포르)
- 관련: [ADR 0012](0012-화면-개편과-데모-예산.md) (데모 예산), [ADR 0011](0011-후속-질문-경로-설계.md) 보완 (벡터 동점 처리), [ADR 0013](0013-Text-to-SQL-통계-어시스턴트-설계.md) (통계 API에 인증 없음)

## 맥락

- 포트폴리오 링크로 눌러 볼 수 있는 데모가 필요하다. 비용은 0원이어야 한다(사용자 결정).
- 샘플 PDF, 근거 청크, 통계 원본은 저장소에 없다(.gitignore). 저장소에서 바로 빌드하는 배포는 데이터 없는 이미지를 만든다.
- 인증 없는 API가 여럿이다. `/api/reports/extract`는 예산 검사 없이 LLM을 부르고, `/api/guidelines/reload`는 누구나 재적재를 일으킨다.

## 결정

1. **호스팅:** 웹은 Render 무료(이미지 배포), DB는 Neon 무료(pgvector 지원, 만료 없음). Render 무료 PostgreSQL은 30일 뒤 만료되어 쓰지 않는다.
2. **이미지:** 로컬에서 샘플 PDF와 근거 청크를 넣어 빌드하고(`Dockerfile`), 비공개 레지스트리에만 올린다. 청크가 공공누리 제4유형이기 때문이다.
3. **여는 범위:** 공개 프로필(`SPRING_PROFILES_ACTIVE=public`)에서 `/api/demo/**`, `/api/ops/llm-usage`, 정적 화면, 액추에이터 health만 연다. 나머지 컨트롤러 메서드는 `PublicDemoConfig`가 404로 막는다. 주소 문자열이 아니라 Spring이 고른 매핑 패턴으로 판단하므로 새 API는 기본이 차단이다.
4. **뺀 것:** ~~결과지 올리기(식별정보 제거가 완전하지 않다)~~(아래 보완에서 열었다), 평가 API, 통계 화면(인증 없음, 100만 행이 무료 저장 한도에 걸릴 수 있음), 임베딩 모델(Ollama).
5. **화면:** 통계 링크와 올리기 요소에 `local-only` 클래스를 붙이고, 이미지 빌드에서만 숨김 규칙을 더하고 `stats.html`을 지운다. 로컬 화면은 그대로다.

## 대안

- **Render 유료(월 약 7달러):** 절전이 없다. 비용 0원 조건으로 제외.
- **컨트롤러마다 조건부로 끄기:** 새 API를 만들 때 끄는 것을 잊으면 열린다. 허용 목록 하나가 기본 차단이라 골랐다.
- **프로필별 정적 화면 복제:** 화면을 고칠 때마다 두 벌을 맞춰야 한다.

## 결과 (로컬 확인, 메모리 512MB 제한 컨테이너 + 빈 DB)

- 기동 약 15초, 마이그레이션 V1~V4 통과. Ollama 없이 뜬다.
- 샘플 해설 200(약 10초), 후속 질문 200(약 13초), 예산 초과 429.
- 막은 API 9종과 주소 우회 3종(`/api;x=1/…`, `/api/demo/../…`, `/%61pi/…`) 모두 404.
- 메모리는 기동 직후 345MB, 해설 후 403MB.

## 결과 (실제 배포, 2026-11-13)

- 샘플 해설 200(첫 추출 포함 약 34초, 로컬 10초보다 느리다. 무료 인스턴스 CPU가 작다), 후속 질문 200(약 6초), 호출 기록이 Neon에 쌓인다.
- 막은 API 6종, 통계 화면, 주소 우회 2종 모두 404.
- Render 무료 메모리는 512MB였다.
- Neon 기본 계정으로 V4의 `stats_reader` 계정 생성이 된다. 다만 Neon은 계정 비밀번호 강도를 검사한다. 약한 `STATS_READER_PASSWORD`로는 V4 커밋이 "insecure password"로 실패해 기동이 멈췄다. 긴 임의 값으로 바꿔 통과했다.
- 서비스의 리전은 만든 뒤에 바꿀 수 없다. 처음에 오리건으로 만들어져 싱가포르로 다시 만들었다.

## 한계

- 15분 무접속이면 Render가 꺼지고, 다시 뜨는 데 1분 안팎이 걸린다.
- 절전 뒤 첫 접속 시간과 예산 초과 429는 배포 환경에서 재지 않았다(429는 같은 이미지로 로컬에서 확인).
- 코드를 고치면 이미지를 다시 빌드해 올리고 Render에서 수동 배포해야 한다. 자동 배포는 없다.
- 근거 청크를 공개 데모 화면에 인용해 보여 주는 것이 공공누리 제4유형 조건에 맞는지는 사용자가 확인한다.

## 보완: 결과지 올리기를 연다 (2026-11-14, 사용자 결정)

**맥락:** 미리 넣은 샘플만 되는 데모보다, 직접 만든 가상 결과지를 올려 볼 수 있는 편이 낫다. Claude는 접근 코드로 잠그는 안을 추천했고, 사용자는 누구나 올릴 수 있게 열되 올리기 전에 확인을 받는 쪽을 골랐다.

**결정**
- 공개 프로필에서 `/api/reports/explain`을 연다(예산 검사를 거친다). 예산 검사가 없는 `/api/reports/extract`는 계속 닫는다.
- 화면에 안내를 두고 확인 상자를 체크해야 파일을 고를 수 있다. 안내 내용: 글자가 외부 AI 서비스(Anthropic)로 전송된다, 식별정보 제거는 완전하지 않다, 검사 수치·성별·나이·검진일은 그대로 간다, 서버는 파일을 저장하지 않고 추출 내용만 메모리에 둔다.
- 공개 프로필의 파일 크기 상한을 2MB로 낮추고(샘플은 60KB 안팎), 올린 결과지 글자 수를 2만 자로 제한한다(샘플은 2천 자 안팎).
- 깨진 PDF와 지원하지 않는 형식은 500이 아니라 415와 안내 문구로 답한다. 형식 오류 처리가 추출 컨트롤러에만 걸려 있어 올리기 경로에서는 500이 나던 기존 결함을 함께 고쳤다.

**확인 (로컬 컨테이너):** 샘플 PDF 올리기 200과 그 결과지의 후속 질문 200, 2만 5천 자 텍스트 413, 3MB 파일 413, 깨진 PDF 415, docx 415, `/api/reports/extract` 404.

**한계**
- 확인 상자는 화면에만 있다. API를 직접 부르면 거치지 않는다.
- 안내와 확인이 개인정보보호법의 민감정보 처리 요건(별도 동의, 처리방침 등)을 채우는지는 검토하지 않았다. 실제 결과지가 올라오면 수치와 일부 식별정보가 외부로 전송된다.
- 올린 문서의 내용은 통제할 수 없다. 가드레일은 합성 결과지로 측정했고, 문서에 지시문을 심는 공격은 재지 않았다.
