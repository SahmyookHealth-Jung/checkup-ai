# 0004. 추출 검증 원칙: LLM은 베끼고, 코드는 원문과 대조하고, 빠진 조각만 다시 묻는다

- 상태: 채택 (2026-11-10)
- 날짜: 2026-11-09 (v2.3·v2.4와 일반화 시험 결과 반영 2026-11-10)
- 관련: ADR 0003 4절(구조화 출력 + 코드 검증 + 재시도)의 구체화

## 맥락

- ADR 0003은 "코드로 검증하고 실패한 항목만 다시 요청한다"고 정했다. 실제로 구현해 보니 **무엇을 다시 묻는지**가 결과를 크게 바꿨다.
- 검증 v1은 재요청에 결과지 전문을 넣었다. 그러자 모델이 "이 줄만"이라는 지시를 무시하고 전체를 다시 추출했다.
  - 반복 26건이 생겼고, 한 보고서는 35분 50초 동안 출력하다 문맥이 찼다.
  - F1이 기준선 0.946에서 0.878로 떨어졌다.
- 소형 로컬 모델(qwen3:4b, CPU)은 반복 루프, 항목 건너뛰기, 비슷한 코드로 오분류하는 실수가 잦다. 반면 **원문에 없는 값을 지어내는 일은 드물었다.** 예외는 항목명과 값이 다른 줄에 있는 가로 표다(heldout-v3에서 원문에 없는 혈압 132/84를 두 번 냈다).
- temperature 0이어도 실행마다 출력이 다르다. 그래서 검증 효과는 같은 실행의 1차 출력과 최종 출력을 짝지어 재야 한다.

## 결정

### 1. 역할 분리
- **LLM:** 원문의 값을 베껴 표준 코드에 배정하는 일만 한다. 계산이나 판단은 시키지 않는다.
- **코드:** 원문을 기준으로 받아들일지 결정한다. LLM 출력은 "후보"일 뿐이다.

### 2. 검증 순서 (원문 대조)
1. 빈 값, 반복(같은 코드 + 같은 값)을 제거한다.
2. 값이 원문에 있는지 확인한다. 숫자는 다른 숫자의 일부(183 속 18, 18.3 속 18)를 인정하지 않는다.
3. 항목 하나의 모양이어야 한다(v2.4). 원문에 있어도 아래 둘은 줄을 통째로 옮긴 것이므로 버린다.
   - 숫자 여러 개가 뭉친 값: 3개년 표 한 줄의 "4.6 4.4 4.3". 범위·분수("0 - 2", "120 / 80")는 한 값으로 본다.
   - 항목명 안에 값이 들어 있는 OTHER 항목: "시력: 좌 0.5 우 0.9"=0.5. 이름 속 숫자(HbA1c, 25-OH)는 값으로 보지 않는다.
4. OTHER 항목은 항목명과 값이 같은 줄에 있어야 한다.
5. 생리적으로 불가능한 값과, 같은 코드(OTHER는 같은 항목명)에 다른 값이 온 충돌을 버린다(먼저 온 값을 남긴다).
6. 참고치 칸에 국가검진 판정 등급(정상A 등)이 들어오면 지운다.
7. 단위·참고치·판정은 값이 있는 줄에 있어야 남긴다. 없으면 null로 바꾼다(지어낸 판정 제거).

**틀린 값보다 빈 값이 낫다.** 필드 검증은 판단이 애매하면 지우는 쪽으로 둔다. 예를 들어 PDF 표 칸에서 두 줄로 줄바꿈된 값은, 필드 검증에서는 두 줄을 함께 보지 않는다. 함께 보면 둘째 줄의 다른 열 값(전회 결과 "정상")이 판정으로 통과한다. 재생 비교에서 함께 보는 방식은 판정 3건을 살리는 대신 필드 8건을 새로 틀리게 했다.

### 3. 재요청: 빠진 조각만
- 원문의 결과 조각(쉼표 단위)을 남은 항목이 "차지"하게 하고, 아무도 차지하지 않은 결과 조각을 "누락 의심"으로 모은다(v2.3).
  - 항목명과 값이 함께 있는 조각은 그 항목이 차지한다. 다른 항목의 같은 값("정상", 74)이 그 줄을 덮지 않게 하기 위해서다.
  - 항목명이 원문에 없는 항목은, 값이 있는 조각 중 아직 아무도 차지하지 않은 것 하나를 차지한다.
- 수검자 정보 줄(단어 목록, 이미 뽑은 검진일이 든 줄), 전화번호·영문 식별자, 안내문은 결과로 보지 않는다.
- 두 줄로 줄바꿈된 값은 누락 검사에서 두 줄을 함께 본다. 둘째 줄을 누락 조각으로 다시 묻지 않기 위해서다.
- 재요청에는 **표 머리 줄과 누락 의심 조각만** 보낸다. 결과지 전문은 보내지 않는다.
- 조각은 4개씩 나눠 보낸다(출력 상한에서 잘리지 않게). 한 묶음이 실패해도 나머지 묶음의 결과는 합친다.
- 재요청 결과도 같은 검증을 거쳐 합친다. 기존 항목은 다시 검사하지 않는다.

### 4. 실패해도 멈추지 않는다
- 출력 상한을 둔다(1차 2,500토큰, 재요청 600토큰). Ollama는 연결을 끊어도 생성을 멈추지 않으므로, 이것이 실제 방어선이다.
- 출력이 상한에서 잘려 JSON이 깨지면, 완성된 마지막 항목까지 살려서 검증을 계속한다. 빠진 부분은 누락 조각 재요청이 채운다. 이를 위해 `BeanOutputConverter`에 위임하는 변환기를 쓰므로 네이티브 구조화 출력은 그대로 동작한다.
- Spring AI 자동 재시도는 1회로 줄인다(기본 10회는 실패한 요청을 계속 쌓았다).
- 재요청이 실패하면 1차 결과를 그대로 반환한다.

### 5. 관측
- 응답에 진단 기록을 남긴다(1차 출력, 문제 목록, 재요청 입력과 출력). 평가는 1차 점수와 최종 점수를 짝지어 기록한다.
- 파이프라인 버전(`validated-v2.2` 등)은 평가 캐시 키에 들어간다. 검증 로직을 바꾸면 버전을 올린다.
- 검증 규칙만 바꿀 때는 **재생 비교**로 먼저 잰다. 저장된 LLM 출력(1차·재요청)에 새 검증기를 적용하는 방식이다. 모델을 부르지 않아 몇 초면 끝나고, 출력 흔들림 없이 규칙의 효과만 볼 수 있다.
  - 도구: `eval/extraction/replay.py`(입력 만들기, 비교)와 `./gradlew :report:replay`(재생).
  - 한계: 새 검증기가 찾은 누락 조각이 실제 실행의 재요청 입력과 다르면, 새 조각에 대한 모델 답이 없다. 그 보고서의 재생 결과는 근사치이므로 도구가 따로 보여 준다.
- 일반화는 **처음 보는 양식**으로 잰다. 양식은 규칙을 정하기 전에 만들고, 그 양식의 결과를 보고 규칙을 고치면 그 양식은 "본 양식"이 된다. 다음 시험은 새 양식으로 한다.

## 검토한 대안
- **결과지 전문으로 재요청(v1)**
  - 기각 이유: 모델이 전체를 다시 추출해 반복과 폭주가 생겼다(F1 0.946 → 0.878).
- **오류 설명을 붙여 LLM이 스스로 고치게 하기(self-correction)**
  - 장점: 구현이 단순하다.
  - 기각 이유: 소형 모델은 지시보다 입력 구성에 더 강하게 반응했다. 판정 기준이 코드에 있는 편이 재현 가능하고 테스트할 수 있다.
- **Spring AI `StructuredOutputValidationAdvisor`**
  - 장점: 기본 제공된다.
  - 기각 이유: JSON 스키마 형식만 검사하고, 원문 대조는 하지 못한다.
- **규칙 기반 파서**
  - 기각 이유: ADR 0003과 같다. 양식마다 규칙이 필요하다.

## 결과 (qwen3:4b, PDF, 합성 결과지)

**개발셋** (양식 3종: 표준 서식, 요약표, 서술형)

| 실행 | 1차 F1 | 최종 F1 |
|---|---|---|
| v2, 6개 | 0.951 | 0.989 |
| v2.1, 30개 중 성공 29개 | 0.950 | 0.993 |
| v2.2 재생 (v2.1과 같은 LLM 출력 29개) | 0.950 | 0.994 |

- v2.1에서 1차 오류 61건 중 54건을 고쳤고, 2건을 새로 만들었다.
- v2.3·v2.4는 개발셋 저장 출력 38개(v2.1 29개, v2.3 9개)에 재생해 결과가 바뀌지 않음을 확인했다. 개발셋 30개 전체 재실행은 하지 않았다.

**처음 보는 양식** (양식마다 10개. 규칙을 정하기 전에 만들고, 결과를 본 뒤에는 그 양식으로 규칙을 고친 버전을 다시 재지 않았다)

| 양식 | 시험한 버전 | 1차 F1 | 최종 F1 | 정밀도 | 재현율 |
|---|---|---|---|---|---|
| 4번째: 검사실 결과지형 (heldout-v1) | v2.2 | 0.806 | 0.905 | 0.979 | 0.843 |
| 5번째: 3개년 추이표형 (heldout-v2) | v2.3 | 0.859 | **0.845** | 0.869 | 0.823 |
| 6번째: 안내문형 (heldout-v3) | v2.4 | 0.902 | **0.926** | 0.939 | 0.913 |

- **원문 대조(2절)는 양식이 바뀌어도 통했다.** 세 양식 모두 1차 출력의 잘못된 항목을 지웠다. heldout-v3에서는 지어낸 혈압과 꼬리말로 만든 가짜 항목을 막았다.
- **누락 탐지와 재요청(3절)은 양식을 탔다.**
  - heldout-v1: 재현율이 개발셋 0.993에서 0.843으로 떨어졌다. v2.3을 만든 계기다.
  - heldout-v2: 재요청이 빠진 항목은 2개만 채우고 쓸모없는 OTHER 항목 21개를 들여와, 최종이 1차보다 낮아졌다. v2.4를 만든 계기다.
  - heldout-v3: 최종이 1차보다 0.024 높았다. 하지만 재요청 조각 45개 중 40개가 꼬리말(주소·쪽 번호)이었다.
- 본 양식이 된 뒤의 재생 비교: heldout-v1은 v2.3에서 0.960이 됐다. heldout-v2는 v2.4에서 0.887이 됐다(같은 LLM 출력, 재요청 입력 변화 0건). 둘 다 일반화 수치가 아니다.
- 양식마다 1차 F1이 0.806~0.902로 다르다. 양식 난이도 차이가 커서, 양식 간 최종 F1 차이를 버전 간 개선으로 읽으면 안 된다. 10개 표본이라 0.03 안팎은 오차 범위다.
- 필드: 판정 지어냄이 247건에서 80건으로 줄었다(개발셋, v2.1). 참고치 칸의 판정 등급 규칙이 맞는 값을 지운 경우는 0건이었다.

## 한계와 열린 문제

추출은 이 ADR로 닫는다(2026-11-10 결정). 아래는 고치지 않고 한계로 남긴다. 모델을 바꾸면(ADR 0005) 다시 잰다.

- **글자 값 대조가 느슨하다.** 글자 값은 조각이 문서 어디에든 있으면 통과한다.
  - "비정상" 자리에 "정상"이 와도 통과한다. 잘린 "비활동성"(원래 "비활동성 폐결핵")도 통과한다.
  - 값에 판정이 붙은 "음성 [양호]"도 통과한다(heldout-v3 남은 FP 13개 중 10개).
- **"같은 줄"은 "같은 칸"이 아니다.** 줄 단위 필드 검증의 근본 한계다.
  - 전회 결과 칸의 "정상"이 판정으로 통과한다.
  - 괄호 속 메모 전체("기준 3.5~5.2 / 지난 검진 4.7")가 참고치로 통과한다(heldout-v3 57건).
  - 가로 표처럼 단위·판정이 다른 줄에 있으면 맞는 값도 지운다. 안전한 쪽의 오류다(heldout-v3 단위 56건, 판정 33건).
- **누락 탐지는 단어 목록과 숫자 모양에 기댄다.** 제목, 주소, 쪽 번호, 상담 안내 줄을 결과로 보고 재요청한다. 재요청이 비용과 지연을 늘리고, 처음 보는 양식에서는 정밀도를 깎을 수 있다(heldout-v2).
- **위험 수치를 조용히 버린다.** 가능 범위 밖의 값(공복혈당 1120 등)은 읽기 오류로 보고 버린다. 그래서 가장 위험한 수치가 해설 단계에 가지 않는다. 의료 가드레일 원칙 3(위험 수치는 진료 권고)과 맞물리므로, 가드레일 단계에서 "확인 필요" 표시로 바꿀지 정한다.
- **오분류 후 손실:** 국가검진 외 항목을 비슷한 국가검진 코드에 넣으면 상식 범위 검사가 버린다. 재요청에서도 같은 실수를 하면 항목이 사라진다. "흉부 촬영"처럼 처음 보는 이름은 OTHER로 빠진다.
- **평가의 한계**
  - OTHER 항목은 값만 맞으면 정답으로 센다(항목명은 보지 않는다).
  - 처음 보는 양식도 생성기의 어휘(음성/정상, 항목 이름)를 개발셋과 공유한다. 그래서 레이아웃 일반화만 잰다. "이상없음", "Negative", "(-)" 같은 실제 표기는 시험하지 않았다.
  - 입력은 텍스트 PDF뿐이다. 이미지·스캔 결과지는 다루지 않는다.
