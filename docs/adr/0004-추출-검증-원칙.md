# 0004. 추출 검증 원칙: LLM은 베끼고, 코드는 원문과 대조하고, 빠진 조각만 다시 묻는다

- 상태: 제안 (사용자 검토 대기)
- 날짜: 2026-11-09
- 관련: ADR 0003 4절(구조화 출력 + 코드 검증 + 재시도)의 구체화

## 맥락

- ADR 0003은 "코드로 검증하고 실패한 항목만 다시 요청한다"고 정했다. 실제로 구현해 보니 **무엇을 다시 묻는지**가 결과를 크게 바꿨다.
- 검증 v1은 재요청에 결과지 전문을 넣었다. 그러자 모델이 "이 줄만"이라는 지시를 무시하고 전체를 다시 추출했다.
  - 반복 26건이 생겼고, 한 보고서는 35분 50초 동안 출력하다 문맥이 찼다.
  - F1이 기준선 0.946에서 0.878로 떨어졌다.
- 소형 로컬 모델(qwen3:4b, CPU)은 반복 루프, 항목 건너뛰기, 비슷한 코드로 오분류하는 실수가 잦다. 반면 **원문에 없는 값을 지어내는 일은 드물었다.**
- temperature 0이어도 실행마다 출력이 다르다. 그래서 검증 효과는 같은 실행의 1차 출력과 최종 출력을 짝지어 재야 한다.

## 결정

### 1. 역할 분리
- **LLM:** 원문의 값을 베껴 표준 코드에 배정하는 일만 한다. 계산이나 판단은 시키지 않는다.
- **코드:** 원문을 기준으로 받아들일지 결정한다. LLM 출력은 "후보"일 뿐이다.

### 2. 검증 순서 (원문 대조)
1. 빈 값, 반복(같은 코드 + 같은 값)을 제거한다.
2. 값이 원문에 있는지 확인한다. 숫자는 다른 숫자의 일부(183 속 18)를 인정하지 않는다.
3. OTHER 항목은 항목명과 값이 같은 줄에 있어야 한다.
4. 생리적으로 불가능한 값과, 같은 코드(OTHER는 같은 항목명)에 다른 값이 온 충돌을 버린다(먼저 온 값을 남긴다).
5. 참고치 칸에 국가검진 판정 등급(정상A 등)이 들어오면 지운다.
6. 단위·참고치·판정은 값이 있는 줄에 있어야 남긴다. 없으면 null로 바꾼다(지어낸 판정 제거).

**틀린 값보다 빈 값이 낫다.** 필드 검증은 판단이 애매하면 지우는 쪽으로 둔다. 예를 들어 PDF 표 칸에서 두 줄로 줄바꿈된 값은, 필드 검증에서는 두 줄을 함께 보지 않는다. 함께 보면 둘째 줄의 다른 열 값(전회 결과 "정상")이 판정으로 통과한다. 재생 비교에서 함께 보는 방식은 판정 3건을 살리는 대신 필드 8건을 새로 틀리게 했다.

### 3. 재요청: 빠진 조각만
- 원문의 결과 조각(쉼표 단위) 중 남은 항목 어디에도 값이 없는 것을 "누락 의심"으로 모은다. 수검자 정보와 안내문은 뺀다.
- 두 줄로 줄바꿈된 값은 누락 검사에서 두 줄을 함께 본다. 둘째 줄을 누락 조각으로 다시 묻지 않기 위해서다.
- 재요청에는 **표 머리 줄과 누락 의심 조각만** 보낸다. 결과지 전문은 보내지 않는다.
- 재요청 결과도 같은 검증을 거쳐 합친다. 기존 항목은 다시 검사하지 않는다.

### 4. 실패해도 멈추지 않는다
- 출력 상한을 둔다(1차 2,500토큰, 재요청 600토큰). Ollama는 연결을 끊어도 생성을 멈추지 않으므로, 이것이 실제 방어선이다.
- 출력이 상한에서 잘려 JSON이 깨지면, 완성된 마지막 항목까지 살려서 검증을 계속한다. 빠진 부분은 누락 조각 재요청이 채운다. 이를 위해 `BeanOutputConverter`에 위임하는 변환기를 쓰므로 네이티브 구조화 출력은 그대로 동작한다.
- Spring AI 자동 재시도는 1회로 줄인다(기본 10회는 실패한 요청을 계속 쌓았다).
- 재요청이 실패하면 1차 결과를 그대로 반환한다.

### 5. 관측
- 응답에 진단 기록을 남긴다(1차 출력, 문제 목록, 재요청 입력과 출력). 평가는 1차 점수와 최종 점수를 짝지어 기록한다.
- 파이프라인 버전(`validated-v2.2` 등)은 평가 캐시 키에 들어간다. 검증 로직을 바꾸면 버전을 올린다.
- 검증 규칙만 바꿀 때는 **재생 비교**로 먼저 잰다. 저장된 LLM 출력(1차·재요청)에 새 검증기를 적용하는 방식이다. 모델을 부르지 않아 몇 초면 끝나고, 출력 흔들림 없이 규칙의 효과만 볼 수 있다.

## 검토한 대안
- **결과지 전문으로 재요청(v1)**
  - 기각 이유: 모델이 전체를 다시 추출해 반복과 폭주가 생겼다(F1 0.946 → 0.878).
- **오류 설명을 붙여 LLM이 스스로 고치게 하기(self-correction)**
  - 장점: 구현이 단순하다.
  - 기각 이유: 소형 모델은 지시보다 입력 구성에 더 강하게 반응했다. 판정 기준이 코드에 있는 편이 재현 가능하고 테스트할 수 있다.
- **Spring AI `StructuredOutputValidationAdvisor`**
  - 장점: 기본 제공된다.
  - 기각 이유: JSON 스키마 형식만 검사하고, 원문 대조는 하지 못한다.
- **규칙 기반 파서**
  - 기각 이유: ADR 0003과 같다. 양식마다 규칙이 필요하다.

## 결과 (qwen3:4b, PDF, 합성 결과지)

| 실행 | 1차 F1 | 최종 F1 |
|---|---|---|
| v2, 6개 | 0.951 | 0.989 |
| v2.1, 30개 중 성공 29개 | 0.950 | 0.993 |
| v2.2 재생 (v2.1과 같은 LLM 출력 29개) | 0.950 | **0.994** |
| **v2.2, 처음 보는 양식 heldout-v1 10개** | 0.806 | **0.905** (P 0.979 / R 0.843) |

- v2.1: 1차 오류 61건 중 54건을 고쳤고, 2건을 새로 만들었다.
- 판정 필드 정확도는 57.5%에서 86.1%로 올랐다. 지어낸 판정이 247건에서 80건으로 줄었다(187건을 지웠고, 재요청 항목이 20건을 새로 들여왔다).
- v2.2: 참고치 필드 정확도가 68.8%에서 81.7%로 올랐다. 판정 등급 규칙이 맞는 값을 지운 경우는 0건이었다.
- 잘린 출력 복구: sum-008이 같은 반복 루프에 다시 빠졌지만, 지난번처럼 실패(0개)하지 않고 23개 중 18개를 맞혔다.
- **일반화:** 처음 보는 양식에서 정밀도는 유지됐다(0.979). 재현율은 0.993에서 0.843으로 떨어졌다. 원문 대조(2절)는 양식과 무관하게 통했지만, 누락 탐지와 재요청(3절)은 기존 3종의 모양에 기대고 있었다.
- 재요청은 29개 중 11개에서 일어났고, 추가 지연은 작았다.

## 한계와 열린 문제
- **누락 탐지가 기존 양식 모양에 기대고 있다** (heldout-v1에서 확인, 최종 누락 36건 분석)
  - 누락 검사는 코드를 보지 않고 값만 본다. 그래서 다른 항목의 같은 값("정상", 74)이 그 줄을 "덮는다"(10건).
  - 쉼표 없이 한 줄에 두 항목이 있으면 하나만 뽑혀도 줄 전체가 덮인다(2건).
  - 수검자 정보 줄을 판별하는 단어 목록이 기존 3종에서 나왔다. 그래서 `등록번호/채혈일` 줄을 매번 재요청했고, 재요청을 오염시켰다(6건).
  - 재요청 출력 상한(600토큰)은 1차가 표 하나를 통째로 건너뛰면 모자란다(18건).
- heldout-v1은 결과를 본 뒤로는 "처음 보는" 양식이 아니다. 규칙을 고치면 다음 일반화 시험은 새 양식으로 한다.
- **"같은 줄"은 "같은 칸"이 아니다.** 줄 단위 필드 검증의 근본 한계로, 남은 필드 오류의 대부분이 여기서 나온다(지어낸 판정 80건).
  - 전회 결과 칸의 "정상"·"음성"이 판정으로 통과한다(sum).
  - 한 줄에 여러 항목이 있는 서술형에서 옆 항목의 판정이 통과한다(nar).
  - PDF에서 두 줄로 줄바꿈된 값은 판정을 지운다(std 3건, 안전한 쪽의 오류).
  - 참고치·판정 칸이 없는 표에서 모델이 값을 그 칸에 다시 써도 통과한다(heldout-v1, 62건).
- **오분류 후 손실:** 국가검진 외 항목을 비슷한 국가검진 코드로 오분류하면, 상식 범위 검사가 버린다. 재요청에서도 같은 실수를 하면 항목이 사라진다.
