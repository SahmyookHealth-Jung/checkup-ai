# 0006. LLM 호출 기록과 외부 전송 전 식별정보 제거: core의 Advisor 두 개로 모든 호출에 건다

- 상태: 채택 (2026-11-10)
- 관련: ADR 0005(기본 Haiku, 식별정보는 로컬 경계에서 차단), CLAUDE.md "LLM을 호출하는 모든 코드는 토큰, 비용, 지연시간을 기록한다", 의료 가드레일 원칙 7(개인정보 최소화)

## 맥락

- ADR 0005로 기본 모델이 외부 API(Claude Haiku 5.5)가 됐다. 검진 결과지에는 이름, 생년월일, 수검번호 같은 식별정보가 들어 있다.
- 다음 단계(RAG 해설, 가드레일 시험, LLM 채점)에서는 호출 종류가 늘어난다. 지금은 추출만 응답에 지표를 싣고, DB 기록은 없다.
- 기능마다 기록·제거 코드를 넣으면 빠뜨리기 쉽다. 그래서 한 곳에서 모든 호출에 걸어야 한다.

## 결정 (사용자, 2026-11-10)

1. **방식:** core에 Spring AI `CallAdvisor` 두 개를 두고, `ChatClientBuilderCustomizer`로 자동 구성되는 모든 ChatClient의 기본 Advisor로 건다. 기능 코드는 호출마다 기능 이름(`LlmCallContext.FEATURE`)만 붙인다.

   | 순서 | Advisor | 하는 일 |
   |---|---|---|
   | 바깥 | `PersonalInfoRedactionAdvisor` | 사용자 메시지의 식별정보를 표시(`[이름]` 등)로 바꾼다. 시스템 메시지는 그대로 둔다. 지운 종류별 개수를 요청 문맥에 남긴다 |
   | 안쪽 | `LlmCallLoggingAdvisor` | 기능 이름, 모델, 입력·출력 토큰, 지연, 비용, 성공·실패, 지운 개수를 `llm_call_log`에 남긴다. 실패한 호출도 기록하고 예외는 그대로 던진다 |

2. **기록 내용은 메타데이터만 남긴다.** 프롬프트와 응답 원문, 지운 식별정보의 값은 저장하지 않는다. 기록 저장이 실패해도 LLM 호출은 실패시키지 않는다.
3. **식별정보 탐지는 규칙 기반으로 한다.**
   - 라벨로 찾는 것: 이름, 성명, 수검번호, 등록번호, 고객번호, 생년월일, 주소 등.
   - 모양으로 찾는 것: 가린 이름(최*준), 가린 생년월일(1965-**-**), 호칭 앞의 이름(○○ 님), 주민등록번호, 전화번호·대표번호, 이메일, 도로명 주소.
   - 남기는 것: 성별, 나이, 검진일. 추출에 필요하다.
4. **항상 적용한다.** 오프라인 모드(로컬 모델)에도 지운다. 두 모드의 입력이 같아 비교할 수 있고, 실수로 외부 모드가 돼도 안전하다. 원문 대조 검증(ADR 0004)은 지우기 전 원문으로 한다.
5. **비용:** 모델별 가격표(100만 토큰당 달러)를 application.yml에 둔다. 출처와 기준일을 주석에 적는다.

## 측정

- **식별정보 잔존율** (`./gradlew :report:piiLeakCheck`)
  - 방법: 합성 결과지 60개(양식 6종)의 PDF 추출 글을 지운 뒤, 생성기가 넣은 식별정보(manifest의 pii)가 남는지 세었다.
  - 결과: **90개 중 0개(0%)**.
  - 개인 정보가 아닌 검진기관 전화번호(20)와 주소(20)도 함께 지웠다. 결과값을 지운 경우는 없었다.
  - 처음 측정에서 오탐 10건을 찾아 고쳤다. PDF에서 표 구분선이 사라져 머리 줄 "성명 생년월일"의 "생년월일"을 이름으로 지운 경우였다.
- **앱 전체 흐름:** sum-001을 지운 글로 추출해 F1 1.000을 확인했다. 기록 한 줄에 기능 이름, 토큰 4,147/1,434, 6.3초, $0.00113, `{"NAME":1,"RECORD_NUMBER":1}`이 남았다.
- 추출 정확도 영향(60개 재실행)은 아래 "결과"에 적는다.

## 검토한 대안

- **Micrometer 관측 핸들러:** Spring AI가 내보내는 관측(OpenTelemetry 이름)을 받아 저장하는 방식이다. 대시보드 연동은 쉽다. 하지만 지운 개수 같은 우리 문맥을 함께 남기기 어렵고 구조가 복잡하다.
- **기능마다 직접 기록·제거:** 단순하지만, 기능이 늘면 같은 코드가 퍼지고 빠뜨리기 쉽다.
- **원문도 기록:** 디버깅은 쉽다. 하지만 가드레일 원칙 7과 충돌한다.
- **로컬 NER 모델로 탐지:** 라벨 없는 실명도 잡는다. 하지만 이 맥에서는 무겁고, 왜 지웠는지 설명하기 어렵다.
- **외부 공급자일 때만 제거:** 모드에 따라 모델 입력이 달라져 비교가 어렵다.

## 한계

- 라벨도 가림표도 없는 실명(예: 표 칸의 "홍길동")은 찾지 못한다.
- 검사 수치는 그대로 나간다. 이 제거는 반출 최소화일 뿐, 비식별 처리의 법적 요건 충족을 뜻하지 않는다.
- 잔존율은 생성기가 만든 합성 식별정보로만 쟀다. 실제 결과지의 다양한 표기(외국인 이름, 다른 번호 형식)는 시험하지 않았다.
- 대표번호 모양(1500-2000)의 수치 범위가 있으면 전화번호로 지울 수 있다. 검진 수치에서는 드물다.
