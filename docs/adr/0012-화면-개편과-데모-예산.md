# 0012. 6단계 화면 개편: Spring 정적 화면 4장, 후속 질문은 샘플에만, 데모 하루 예산 상한

- 상태: 채택 (2026-11-12, 사용자 "시작해봐. 어차피 완료 후 수정되잖아")
- 관련: ADR 0007(최소 화면, 공개 데모는 샘플만), ADR 0006(LLM 호출 기록), ADR 0011(후속 질문 경로와 한계), PROJECT_BRIEF 변경 이력 2026-11-10(화면은 Spring 안에서, React 없음)

## 맥락

5단계까지 화면은 해설 데모 한 장이었다. 지원 직무에서 보여 줄 것은 측정·개선과 운영이다. 그래서 결과와 한계를 보여 주는 화면이 필요하다. 후속 질문 경로(ADR 0011)는 평가 API로만 열려 있다.

## 결정

1. **화면 4장, 빌드 없는 정적 HTML** (`backend/app/src/main/resources/static/`). 공통 스타일 한 파일과 위쪽 메뉴를 둔다.
   - 소개(`index.html`): 무엇을 하고 무엇을 하지 않는지, 대표 수치와 한계, 화면 안내.
   - 해설 데모(`demo.html`): 기존 해설 화면 + 후속 질문 패널.
   - 품질(`quality.html`): 평가 결과. 데이터는 `eval/build_dashboard_data.py`가 커밋된 평가 기록(`eval/results/index.jsonl`)과 주요 결과를 `static/data/quality.json`으로 묶는다. 앱은 실행 중에 평가 파일을 읽지 않는다.
   - 운영(`ops.html`): `llm_call_log`를 기능별·날짜별로 집계한 API(`/api/ops/llm-usage`)로 호출 수, 실패, 토큰, 비용, 지연을 보여 준다. 원문은 기록에 없으므로 메타데이터만 나간다(가드레일 원칙 7).
   - 차트는 외부 라이브러리 없이 SVG로 그린다.
2. **후속 질문은 합성 샘플에만 연다.** `POST /api/demo/samples/{id}/followup {question, itemCodes}`.
   - 결과지는 클라이언트가 보내지 않고, 서버가 그 샘플의 추출 결과를 쓴다. 해설할 때 추출한 것을 메모리에 두고 다시 쓴다. 클라이언트가 보낸 결과지(검증을 거치지 않은 값)가 LLM에 가지 않는다(ADR 0007 7절과 같은 이유).
   - 질문은 300자까지 받는다.
   - 화면에 "진단 질문을 놓칠 수 있다"는 한계(ADR 0011 보완 결과)를 적는다.
3. **데모 하루 예산 상한.** 오늘(서버 시간대) `llm_call_log`의 비용 합이 `checkupai.llm.daily-budget-usd`(기본 $0.20) 이상이면, 데모 호출(샘플 해설, 업로드 해설, 후속 질문)을 429로 막는다. 평가 API는 막지 않는다(개발 측정용, 공개 배포에서는 꺼 둔다).

## 대안

- **React/Vite 화면:** 빌드 단계와 설명할 기술이 늘어난다. 보여 줄 것은 측정과 운영이라 택하지 않았다(PROJECT_BRIEF 2026-11-10).
- **후속 질문에 결과지를 클라이언트에서 받기:** 평가 API와 같은 모양이라 간단하지만, 검증을 거치지 않은 값이 LLM에 간다.
- **품질 화면이 평가 파일을 실행 중에 읽기:** 앱이 eval/ 폴더 위치에 묶인다.
- **예산 상한을 요청 수로:** 비용이 요청마다 달라서(해설 $0.002 안팎, 추출 포함 시 더 큼) 돈으로 막는 쪽이 정직하다.

## 한계

- 추출 결과 메모리 저장은 앱을 다시 띄우면 사라진다. 샘플 수가 작아 상한을 두지 않았다.
- 예산 확인과 호출 사이에 여러 요청이 동시에 들어오면 상한을 조금 넘을 수 있다.

## 보완: 가상 결과지 올리기와 후속 질문 (2026-11-13, 사용자 요청)

- 해설 데모에서 직접 만든 가상 결과지(글자가 있는 PDF·txt)를 올릴 수 있게 했다. 서버의 업로드 해설 API(`POST /api/reports/explain`)는 원래 있었고 화면에만 없었다.
- 올린 결과지에도 후속 질문을 받는다. 서버가 추출 결과를 메모리에 두고 추측할 수 없는 id(`up-` + 24자리 16진수)를 돌려준다. 후속 질문은 샘플과 같은 경로(`/api/demo/samples/{id}/followup`)로 받고, 클라이언트가 보낸 결과지가 아니라 서버가 추출한 값을 쓴다.
- 기억은 최근 50개까지만 하고 오래된 것부터 지운다. 디스크와 DB에는 남기지 않고, 앱을 다시 띄우면 사라진다. 원문은 저장하지 않는다(호출 기록에는 토큰·비용만 남는다).
- 올린 결과지도 외부 전송 전 식별정보 제거와 하루 예산 상한을 똑같이 거친다. 그래도 실제 결과지를 올리지 말라는 안내는 화면에 그대로 둔다. 공개 배포에서 업로드를 막을지는 배포 때 정한다.
- 확인: 처음 보는 txt 양식(가상 "하늘빛의원", 17항목)을 올려 17항목이 모두 맞게 추출·판정됐고, 같은 결과지에 후속 질문 1개가 출처와 함께 답됐다. Haiku 약 5회.
