# 0001. 기술 스택 선정

- 상태: 채택
- 날짜: 2026-11-08

## 맥락

- 포트폴리오 목표는 "AI 기능을 실서비스에 붙이고 측정·개선하는 Java 백엔드 개발자"다. 그래서 Java/Spring 생태계 안에서 LLM을 다루는 것이 핵심이다.
- 저비용이 원칙이다. 개발은 로컬 모델, 평가·데모는 저가 API로 하고, 설정만 바꿔 모델을 교체할 수 있어야 한다.
- 환경 점검 결과, 개발 머신은 **Intel Mac**(i7-8850H 6코어, 16GB, Radeon Pro 560X)이었다. Ollama는 이 GPU를 쓰지 못해 CPU로만 추론한다.
- 브리프는 Spring Boot 3.x를 가정했다. 그런데 2026-11-08 기준 start.spring.io는 4.1.2(기본)와 4.0.9만 제공한다. Spring AI 스타터도 Boot 4.0 이상에서만 선택할 수 있다.

## 결정

| 영역 | 선택 | 메모 |
|---|---|---|
| 언어 | Java 21 (Temurin) | LTS. Gradle toolchain으로 고정 |
| 프레임워크 | Spring Boot 4.1.2 | 현재 GA |
| AI | Spring AI 2.0.1 | `ChatModel`/`EmbeddingModel`/`VectorStore` 추상화. `spring.ai.model.chat=ollama\|anthropic`으로 공급자를 교체 |
| 빌드 | Gradle 9.8 (Kotlin DSL) + 버전 카탈로그 + buildSrc 컨벤션 | 멀티모듈 구조는 ADR 0002 |
| DB | PostgreSQL 18.6 + pgvector 0.8.7 | 이미지 `pgvector/pgvector:0.8.7-pg18`. 벡터와 관계형 데이터(로그, 기능 2 통계)를 한 DB에서 처리 |
| 스키마 관리 | Flyway | 벡터 테이블과 로그 테이블을 버전 관리. Spring AI의 `initialize-schema`는 끈다 |
| 임베딩 | Ollama + bge-m3 (1024차원, F16) | 다국어(한국어) 성능, 무료, 로컬 |
| 로컬 채팅 모델 | **미정** | 결과지 추출 작업 때 후보를 실측해 정한다 |
| API 채팅 모델 | Claude Haiku 계열 (`claude-haiku-5-5`) | 평가·데모, 품질이 중요한 개발 작업 |
| Ollama 실행 방식 | macOS 네이티브 앱 (컨테이너 아님) | Docker VM을 거치면 CPU 추론이 더 느려지고 메모리가 이중으로 든다 |

## 검토한 대안

- **Spring Boot 3.5 + Spring AI 1.x**
  - 장점: 현업에서 많이 쓰이고 예제가 많다.
  - 기각 이유: start.spring.io에서 빠졌고 오픈소스 지원이 끝났다. 새 프로젝트로 고르기엔 근거가 약하다.
- **Maven**
  - 장점: SI에서 익숙하고 구조가 명확하다.
  - 기각 이유: 멀티모듈 설정이 장황하다. 국내 서비스 회사는 대부분 Gradle을 쓴다.
- **별도 벡터 DB(Qdrant, Chroma 등)**
  - 장점: 벡터 검색 기능이 풍부하다.
  - 기각 이유: 운영할 저장소가 하나 늘어난다. 키워드 검색, 로그, 기능 2 통계를 PostgreSQL 하나로 처리하는 편이 단순하다.
- **Ollama를 Docker로 실행**
  - 장점: 배포 환경과 같아진다.
  - 기각 이유: Intel Mac에서는 이점이 없고 느리다. 배포 단계(6주차)에서 다시 검토한다.

## 결과

**좋은 점**
- 코드는 Spring AI 추상화에만 의존한다. 그래서 Ollama ↔ Claude 교체가 `application.yml` 한 줄로 끝난다.
- 로컬 개발 비용이 0원이다.

**감수할 점**
- Spring AI 2.x는 인터넷 예제(대부분 1.x)와 설정 키·API가 다르다. 예: `spring.ai.ollama.embedding.options.model` → `spring.ai.ollama.embedding.model`. jar 메타데이터나 공식 문서로 확인하는 습관이 필요하다.
- 로컬 채팅 모델은 CPU 추론이라 느리고 품질에도 한계가 있다. 품질 검증은 API 모델로 하고, 로컬 모델은 연결 확인과 반복 개발에 쓴다.
- 로컬에 설치된 PostgreSQL 17(EDB)이 5432를 쓰고 있어 컨테이너는 **5433**을 쓴다.
