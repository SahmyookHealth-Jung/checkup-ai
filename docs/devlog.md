# 개발 일지

## 2026-11-08 (1주차 1일): 환경 구성과 프로젝트 골격

### 한 일

- **개발 환경 점검**
  - 이 머신이 브리프의 가정(Apple Silicon)과 달리 **Intel Mac**(i7-8850H, 16GB)인 것을 확인했다.
  - Homebrew는 Intel macOS용 미리 빌드된 포뮬러를 더 이상 주지 않는다. 그래서 cask로 설치했다.
    - Ollama: `ollama-app` 0.40.15
    - JDK: `temurin@21` 21.0.13
  - Docker Desktop 28.0.4는 이미 설치돼 있었다.
- **스택 확정:** start.spring.io에서 Spring Boot 3.x가 빠져 있었다. 그래서 Boot 4.1.2 + Spring AI 2.0.1로 정했다([ADR 0001](adr/0001-기술스택-선정.md)).
- **구조 확정:** Gradle 멀티모듈(`core` / `report` / `app`, 이후 `stats`)로 정했다([ADR 0002](adr/0002-저장소-모듈-구조.md)).
- **Docker Compose:** PostgreSQL 18.6 + pgvector 0.8.7을 띄웠다. Flyway V1으로 `vector` 확장을 켰다.
- **Spring AI 연결 확인:** 통합 테스트 3개가 통과했다.
  - 앱 기동과 pgvector 확장 확인
  - bge-m3 임베딩이 1024차원으로 나옴
  - 의미가 가까운 문장의 코사인 유사도가 더 높음
- **Ollama 내부 구조 확인:** 구조는 `Ollama.app → ollama serve(:11434) → llama-server(러너)` 3단이다.
  - 러너는 요청이 올 때 모델을 메모리에 올리고, 5분 동안 요청이 없으면 내린다(keep_alive).
  - 모델은 Docker 이미지처럼 manifest와 sha256 이름의 blob으로 저장된다.

  - 방해 요소를 넣었다: 전회 결과 칸, 소견 속 전회 수치, 나이 미표기.
  - 생성할 때 정답이 문서와 일치하는지 자동으로 검사한다. 이 검사로 정답 불일치 2건을 바로 발견해 고쳤다.

- **평가 스크립트**(`eval/extraction`)
  - 대표 지표는 **항목 F1(code+value)**이다(사용자 결정).
  - 응답을 캐시하고, 결과를 `eval/results/extraction/history.md`에 쌓는다.
- **검증 v1**(`validated-v1`): 반복 제거, 원문 대조, 상식 범위 검사, 누락 의심 줄 재요청.

### 오류 분석에서 배운 것
- **기준선 오류는 "지어내기"가 아니라 반복과 누락이었다.**
  - 목록 끝에서 같은 항목을 반복 출력했다.
  - 그 자리에서 추가 검사(OTHER)와 시력 행을 건너뛰었다.
  - 그래서 검증 설계를 "지어내기 차단" 중심에서 "반복 제거·누락 복구"로 바꿨다.
- **PDF 추출기(PDFBox 배치 보존 모드)는 칸 안 단어 사이에도 공백을 많이 넣는다**(`비활동성     폐결핵`). 모델이 이 공백을 칸 경계로 읽어 값이 잘렸다. 입력 토큰도 낭비된다.
- **검증 v1의 실패 원인**(Ollama 서버 로그의 요청별 소요 시간으로 추적)
  - 재요청 프롬프트에 결과지 전문을 넣었더니, 모델이 "이 줄만"이라는 지시를 무시하고 전체를 다시 추출했다.
  - sum-002에서는 반복 루프에 빠져 문맥(8192)이 찰 때까지 35분 50초 동안 출력했다.
  - 출력 토큰 상한과 앱 쪽 호출 시간 제한이 없어서 멈출 장치가 없었다.
- **temperature 0이어도 실행할 때마다 출력이 조금씩 다르다.** 기준선에서 맞힌 OTHER를 v1의 1차 추출에서는 놓쳤다. 그래서 파이프라인을 공정하게 비교하려면 같은 1차 출력에 검증만 적용해 비교해야 한다.
- 한 줄에 여러 항목이 있는 서술형은 줄 단위 커버리지 검사로 누락을 못 찾는다(시력).

- **재개 가능한 평가 스크립트**(`eval/run_eval_resumable.sh`): DB, Ollama, 앱을 켜고 `caffeinate`로 잠자기를 막는다. 꺼졌다 켜져도 같은 명령으로 이어서 돈다(응답 캐시).

  1. 누락 탐지가 제목("건강검진 3개년 추이 보고서"), 상담 안내 줄("1588-0000 (평일 09:00~18:00)"), 시력·청력 한 줄을 빠진 결과로 봤다.
  2. 모델은 재요청에서 줄 전체를 항목명으로 베꼈다. OTHER 검사(이름과 값이 같은 줄)는 이름이 줄 전체이면 늘 통과한다.
- **v2.2의 결론이 한 단계 더 나갔다.** v2.2에서는 "정밀도 장치는 일반화되고 재현율 장치는 과적합"이었다. 이번에는 재현율 장치(재요청)가 정밀도까지 깎았다. 처음 보는 양식에서는 재요청이 손해일 수 있다.
- **남은 누락 37건은 대부분 1차에서 이미 놓친 것이다.** 시력·청력 한 줄(4개 항목 × 5개 보고서), 3개년 칸에서 올해 값을 못 고른 추가 검사, 신체계측 일부다.
- **남은 FP 7건은 일부러 두었다.**
  - 값 "-"(3건): 소변 검사에서 "-"는 음성이라는 뜻이라, 빈 값 표시로 지우면 맞는 결과를 잃는다.
  - 지난해 값을 고른 경우와 오분류: 줄 모양만으로는 구분할 수 없다.

### Claude Code 협업

**잘 된 점**
- heldout-v2는 v2.3을 만들기 전에 생성해 두었고, 결과를 본 뒤에도 그 결과로 v2.3을 고치지 않았다. 그래서 0.845는 정직한 수치로 남았다.

**막힌 점**
- 지난 실행의 발열 기록기가 `kill`로 꺼지지 않고 남아 기록이 두 줄씩 쌓였다. 직접 찾아 종료했다. 이번 실행 뒤에도 남아 있는지 확인해야 한다.
