# 작업 지시: 후속 질문 근거 인용 개선 (측정 장치부터)

- 작성: 2026-11-14, 사용자 승인. 다른 세션이 이 문서만 읽고 시작할 수 있게 썼다.
- 관련: [ADR 0011](../adr/0011-후속-질문-경로-설계.md)(후속 질문 경로와 보완 두 번), [ADR 0014](../adr/0014-후속-질문-진단-거절-보강.md)(진단 거절 층), 저장소 루트 `CLAUDE.md`(협업 규칙).

## 왜 하는가

README의 후속 질문 수치가 목표에 못 미친다. 시험 40문항에서 답 가능 18문항 중 정답 절을 인용해 답한 것이 8~10건이다(목표 80%).

받은 피드백은 세 가지다.

1. 검색, 답 생성, 인용 검증을 분리해 어느 단계에서 실패하는지 추적하라.
2. 근거가 약하면 짧게 보류하는 동작을 평가하라.
3. 진단 요청 분류가 새 문항 36건 중 1건을 놓쳤고, 같은 질문도 분류가 달라진다.

저장소와 대조한 결과 세 가지 모두 사실이다.

## 지금 상태 (2026-11-14 확인)

**단계별 추적은 자동으로 되지 않는다.** 답 평가 기록(`eval/rag/run_followup_answer_eval.py`)에는 문맥 글자 수만 있고, 정답 절이 문맥에 들어갔는지가 문항별로 없다. 문맥 평가는 별도 실행(`run_followup_context_eval.py`, `check_followup_context.py`)이라 두 기록을 손으로 맞춰야 한다.

**실패 원인은 문항셋마다 다르다.** 최근 실행 `ground1-after`(답 가능 29문항)를 손으로 나눈 결과다. 정답 절이 문맥에 있었는지는 이 분류에 들어 있지 않다.

| 원인 | 항목 고름 (실패 6) | 항목 안 고름 (실패 7) |
|---|---|---|
| 모델은 답했는데 코드가 진단 거절로 덮어씀 | 4 | 2 |
| 모델이 "근거 없음"으로 물러섬 | 0 | 3 |
| 같은 문서의 다른 절을 인용 | 1 | 2 |
| 답 문장이 구절 대조에서 전부 지워짐 | 1 | 0 |

- 과잉 거절 4건은 층이 각각 다르다: 규칙 1(fg-013), 질문 분류 1(fg-023), 답 검사 2(fg-009, fg-028).
- 구절 대조에서 전부 지워진 것은 fg-024 "혈색소 10.6이면 남자 기준으로 어디에 들어가요?"다. 판정기준표만 있으면 답할 수 있는 질문이다. 왜 지워졌는지는 보지 않았다.
- 시험 40문항의 실패는 다른 모양이었다(같은 문서의 다른 절 인용, 근거 없음 3~4건. ADR 0011 3단계).

**재지 않은 것**
- `eval/followup/followup-boundary-v1.jsonl`(답 가능 18, 진단 요청 12)은 커밋만 되고 한 번도 실행되지 않았다.
- 진단 분류가 같은 질문에서 얼마나 자주 뒤집히는지. 알려진 사례는 fr2-010 하나다.
- 답할 수 있는데 보류한 건수를 따로 둔 지표, 근거가 일부만 있는 질문에서 나머지를 보류했는지.

## 작업 순서

| 순서 | 작업 | 완료 기준 | LLM 비용 (추정) |
|---|---|---|---|
| 1 | 단계별 실패 분류를 평가 기록에 넣는다 | 답 평가 기록의 문항마다 원인이 하나씩 붙고, 요약에 단계별 건수 표가 나온다. 단위 테스트가 있다 | 0 |
| 2 | 현재 코드로 기준선을 잰다 | `followup-ground-v1`과 `followup-boundary-v1`의 단계별 표가 `eval/results/`에 `dirty=false`로 남는다 | 약 $0.2 |
| 3 | 진단 분류의 흔들림을 잰다 | 같은 질문을 5회씩 분류해 문항별로 뒤집힌 횟수가 남는다 | 약 $0.05 |
| 4 | 보류 평가용 문항과 지표를 만든다 | 근거가 일부만 있는 질문 세트가 구현 전에 커밋되고, 보류 지표의 정의가 측정 전에 커밋된다 | 0 |
| 5 | **멈추고 사용자에게 보고한다** | 2~3의 표와 고칠 후보를 보여 준다. 사용자가 고칠 단계와 방식을 정한다 | 0 |
| 6 | 정한 것을 고치고 개발 몫에서 확인한다 | 5에서 정한다 | 약 $0.2~0.5 |
| 7 | 새 시험 문항으로 한 번 잰다 | README와 품질 화면 수치를 갱신한다 | 약 $0.4 |

비용은 지난 실행(Haiku 80회 $0.09)에서 추정했다. 실제 금액은 `llm_call_log`로 확인한다.

### 1. 단계별 실패 분류

문항마다 아래 중 하나를 붙인다. 위에서부터 먼저 맞는 것을 고른다.

| 원인 | 조건 |
|---|---|
| 거절 층 | 답 가능 문항인데 규칙, 질문 분류, 답 검사 중 하나가 진단·치료 거절로 바꿨다. 어느 층인지도 남긴다 |
| 검색 | 정답 절이 문맥에 하나도 없다 |
| 생성: 보류 | 정답 절이 문맥에 있는데 모델이 "근거 없음"으로 답했다 |
| 인용 검증 | 모델이 문장을 만들었는데 구절 대조에서 전부 지워졌다 |
| 생성: 다른 절 | 답했지만 정답 절을 인용하지 않았다. 같은 문서인지도 남긴다 |
| 통과 | 정답 절을 인용해 답했다 |

- 필요한 변경: 평가용 답 응답(`EvalFollowupController`의 `/api/eval/followup/answer`, `FollowupService.Metrics`)에 문맥에 넣은 절 id 목록을 싣는다. 평가 스크립트가 정답 절(`expectedSections`)과 비교한다.
- 서비스 동작은 바꾸지 않는다. 기록만 더한다.
- 답하면 안 되는 문항(답 불가, 거절, 악성)에는 지금의 건수 지표를 그대로 둔다.

### 2. 기준선

```bash
cd eval
.venv/bin/python -m rag.run_followup_answer_eval --gold followup/followup-ground-v1.jsonl --split ground1 --runs 1 --label ground1-stages
.venv/bin/python -m rag.run_followup_answer_eval --gold followup/followup-boundary-v1.jsonl --split <파일의 split 값> --runs 1 --label boundary1-baseline
```

- 옵션 이름과 `split` 값은 스크립트와 정답셋 파일에서 확인하고 쓴다. 위 명령은 형태를 보인 것이다.
- 로컬 앱(`./gradlew :app:bootRun`)과 Ollama가 떠 있어야 한다. 기본 프로필로 잰다(벡터 동점 처리 켜짐).

### 3. 분류 흔들림

- 대상: `followup-recheck-v2`와 `followup-boundary-v1`의 진단 요청 문항, 그리고 답 가능 경계 문항.
- 질문 분류 호출만 5회씩 반복한다. 분류만 부르는 평가 경로가 없으면 평가용으로 하나 만든다(공개 프로필에서는 닫혀 있어야 한다).
- 남길 것: 문항별 5회 결과, 한 번이라도 뒤집힌 문항 수, 놓침 방향과 과잉 거절 방향을 따로.

### 4. 보류 평가

- 지표: 답 가능·답 불가 × 답함·보류의 네 칸을 건수로. "답할 수 있는데 보류"와 "답하면 안 되는데 답함"을 나란히 둔다.
- 새 문항: 근거가 일부만 있는 질문(두 가지를 묻는데 하나만 문서에 있음). 규칙과 프롬프트를 보지 않은 **별도 세션**이 쓰고, 사용자가 근거 절을 검토한 뒤 커밋한다.
- 보류 문구는 고정 문구라 길이는 재지 않는다.

## 지켜야 할 규칙

- **시험 40문항(`followup-v1`의 시험 몫)은 다시 재지 않는다.** 실패 분석으로 이미 열어 봤다. README 수치는 7번의 새 문항으로만 갱신한다.
- **측정 세트는 고치는 쪽이 모르게 만든다.** 문항은 구현 전에 커밋하고, 구현하는 세션은 새 시험 문항을 열어 보지 않는다.
- **비교 수치는 커밋한 코드로만 잰다**(기록의 `git.dirty`가 false).
- **5번 전에는 서비스 동작을 고치지 않는다.** 고칠 단계와 방식(검색 전략, 프롬프트, 가드레일)은 사용자가 정하고 ADR로 남긴다.
- 핵심 로직은 커밋 직전에 사용자가 Codex 리뷰를 돌린다. 커밋 전에 바꾼 내용을 요약해 보여 준다.
- 비용이 예상을 넘으면 멈추고 묻는다.

## 알아 둘 제약

- **분류를 온도 설정으로 고정할 수 없다.** `application.yml` 주석에 따르면 Haiku 5.5는 기본값이 아닌 샘플링 값을 거절한다. 이 주석은 2026-11-14에 API 문서로 다시 확인하지 않았다. 흔들림을 줄이려면 여러 번 불러 하나라도 진단이면 거절하는 식의 구조가 필요하고, 그만큼 과잉 거절이 늘 수 있다. 그래서 놓침과 과잉 거절을 항상 함께 잰다.
- **목표 80%가 도달 가능한지는 2번 결과를 봐야 안다.** 실패가 "같은 문서의 다른 절 인용"에 몰려 있으면 답의 품질이 아니라 정답 라벨의 단위 문제일 수 있다. 라벨 기준을 결과를 본 뒤에 바꾸지 않는다. 바꾸려면 새 문항에 측정 전에 적용한다.
- 지금까지 효과가 없던 것: "근거 없음" 재확인 호출(되돌림), 해설 프롬프트에 규칙 한 줄 더하기. 효과가 측정된 것은 구조를 바꾼 경우였다(질문 분류 단계 분리).
- 공개 데모는 벡터 동점 처리를 끈 구성이다(ADR 0011 보완). 그 구성의 답 품질은 재지 않았다. 이 작업의 범위는 아니지만 2번에서 같은 세트를 그 설정으로 한 번 더 재면 차이를 알 수 있다.
