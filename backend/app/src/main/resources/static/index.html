검진 결과 해설 AI 소개해설 데모품질운영

포트폴리오 · 합성 데이터만 사용 · 2026

건강검진 결과지를 읽고, 국가 기준으로 판정하고,
공개 문서를 근거로 설명합니다.

LLM은 결과지의 값을 베끼고, 근거가 있는 곳에서만 문장을 씁니다. 판정과 진료 권고, 고지, 받아들일지 여부는 코드가 정합니다. 어디에 LLM을 쓰고 어디에 쓰지 않을지는 측정으로 정했습니다. 진단은 하지 않습니다.

해설 데모 →품질 수치와 실패 기록 →운영 기록 →

처리 순서

단계하는 일맡은 쪽
1결과지 PDF에서 항목·값·단위를 뽑는다LLM (Haiku 5.5, 구조화 출력)
2뽑은 값이 원문에 있는지 대조하고, 없으면 받지 않는다코드
3보건복지부 고시 판정기준표로 정상A·정상B·질환의심을 정한다코드
4항목 코드로 공개 문서(질병관리청 등 9편)의 절을 찾는다코드
5근거를 인용한 해설 문장을 쓰고, 인용과 숫자를 검증해 통과한 문장만 남긴다LLM + 코드 검증
6위험 수치에 진료 권고를, 모든 응답에 고지문을 붙인다코드

결과를 본 뒤 묻는 후속 질문은 항목으로 범위를 좁혀 근거를 찾습니다(글자 2-gram BM25). 진단·약 질문과 근거 없는 질문에는 정해진 문구로 답합니다.

못 한 것과 한계

  1. 후속 질문은 시험 통과 규칙을 채우지 못했습니다. 진단 질문 2건에 답했고, 진단 규칙을 더한 뒤에도 새 문항의 진단 질문 8개 중 2개를 놓쳤습니다.
  2. 결과지는 모두 합성 데이터입니다. 글자 층이 있는 PDF만 다루고 스캔 이미지는 다루지 않습니다.
  3. 라벨러는 개발자 1명이고 의료인이 아닙니다. 채점기와 리뷰에 같은 계열 모델(Claude)이 많습니다.

기술

Java 21, Spring Boot 4, Spring AI 2, PostgreSQL 18 + pgvector, Claude Haiku 5.5, Ollama(bge-m3 임베딩, 오프라인 모드 qwen3:4b), Python 평가 스크립트. 모든 LLM 호출은 토큰·비용·지연을 기록하고, 보내기 전에 식별정보를 지웁니다. 데모 호출은 하루 예산 상한을 지킵니다.
